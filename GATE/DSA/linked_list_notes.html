Section 01

What is a Linked List?

The Problem it Solves

An array is a fixed block of memory. When you declare int arr[10], you reserve 10 slots. The problem: you must decide the size before you start. You cannot easily grow or shrink it, and inserting/removing in the middle is slow because all elements must shift.

A linked list solves this by storing elements one by one in heap memory. Each element knows where the next one is. You never need to decide the size in advance, and insertion/deletion is very fast if you are at the right place.

Goal
A dynamic data structure where elements can be added/removed at any time without wasting or pre-reserving memory.

What Does it Look Like?

A linked list is a chain of nodes. Each node holds two things:

  1. data — the actual value (like an integer)
  2. next — an address (pointer) to the next node

The last node's next points to NULL, meaning "end of list". There is also a special pointer called Head that always points to the first node.

Head │ ▼ ┌──────┬──────┐ ┌──────┬──────┐ ┌──────┬──────┐ ┌──────┬──────┐ │ 4 │ ●───┼────>│ 15 │ ●───┼────>│ 7 │ ●───┼────>│ 40 │ NULL │ │ data │ next │ │ data │ next │ │ data │ next │ │ data │ next │ └──────┴──────┘ └──────┴──────┘ └──────┴──────┘ └──────┴──────┘ addr: 1000 addr: 2000 addr: 3000 addr: 4000
✦ The magic idea
The nodes do NOT need to be next to each other in memory. They can be anywhere on the heap. The pointer is the chain that connects them. This is the fundamental insight of a linked list.
Section 02

Anatomy of a Node (Memory Model)

Struct Definition in C

In C, a node is defined as a struct. It contains data AND a pointer to another node of the same type — this self-referential pointer is the chain link.

struct node {
    int data;             // holds the value
    struct node *next;    // pointer to the next node (same type!)
};

How Memory Works (Stack vs Heap)

When you write int x; it goes on the stack — local, fast, automatically freed.

When you write malloc(...) it allocates on the heap — lives as long as you want, you must free it manually.

Linked list nodes live on the heap. Each node is created with malloc.

// Creating a new node step by step:
struct node *p = malloc(sizeof(struct node));
                 // ^^ allocates exactly enough heap space for one node

p->data = 5;     // set the value
p->next = NULL; // no next node yet
Key Pointer Rule
p->data means: "go to where p points, then access data."
p->next means: "go to where p points, then access next."
If q = p->next, then q now points to the NEXT node.

Size of a Node

struct node x; // size = 4 bytes (int) + 8 bytes (pointer) = 12–16 bytes sizeof(int *) = 8 // on 64-bit systems sizeof(char *) = 8 sizeof(void *) = 8 // all pointers same size on same system

Understanding Node Linking

Given two nodes x at address 1000 and y at address 2000:

struct node x, y;
struct node *p;

p = &x;             // p points to node x (address 1000)
x.next = &y;        // x's next points to y
// OR equivalently: p->next = &y

y.next = NULL;      // y is the last node

// Accessing y's data through the chain:
p->next->data       // same as x.next.data = y's data
Section 03

Traversal — How to Walk the List

To visit every node, you start from head and keep moving to ->next until you reach NULL.

⚠ Never modify head directly during traversal
Always use a temporary pointer like current or temp. If you move head forward, you lose access to the beginning of the list forever. 
// Print all elements
void printList(struct node *head) {
    struct node *current = head;   // temp pointer, head stays safe
    while (current != NULL) {
        printf("%d ", current->data);
        current = current->next;    // move to next node
    }
}

// Count length
int length(struct node *head) {
    int count = 0;
    while (head != NULL) {
        count++;
        head = head->next;
    }
    return count;
}

Accessing the Nth element

head -> next -> data = 2nd element's value head -> next -> next -> data = 3rd element's value head -> next -> next -> next = 4th node's address

This is O(n) — you must walk from the beginning every time. There is no "jump to index 3" like arrays.

Section 04

Array vs Linked List

Property Array Linked List
Memory layout Contiguous (all together) Scattered (anywhere on heap)
Size Fixed at declaration Dynamic — grows/shrinks anytime
Random access O(1) — direct by index O(n) — must traverse from head
Insert/Delete at front O(n) — shift all elements O(1) — just update head pointer
Insert/Delete in middle O(n) — shift elements O(1) if pointer already at position
Cache locality Excellent — elements in cache together Poor — nodes spread across memory
Memory overhead No extra overhead per element Each node stores an extra pointer (8 bytes)
Binary search possible? Yes No (can't jump to middle)

Cache Locality — Why Arrays are Faster in Loops

The CPU has a small, fast cache memory. When you access a[0], the CPU also loads a[1], a[2], a[3]... into cache automatically (this is called a cache line). So a[1] is super fast — already in cache.

For a linked list, each node is at a random address. When you access node 1, the CPU cannot predict where node 2 is. Each access may be a cache miss — slow round trip to main memory.

Array traversal: a[0] → little slow (first access, loads into cache) a[1] → SUPER FAST (already in cache!) a[2] → SUPER FAST (already in cache!) Linked list traversal: node at 1000 → slow (loads to cache, but next node is elsewhere) node at 8540 → slow (cache miss, go to main memory again) node at 3120 → slow (cache miss again...)
When to choose which
Use Array when: size is known, you need random access, you loop through data often.
Use Linked List when: size is unknown/changing, you need many insertions/deletions at the front.

Real-World Use Cases

🎵 Music Playlist

Each song is a node. It has the song data and a pointer to the next song. "Previous" and "Next" buttons are just prev and next pointers — a Doubly Linked List.

cheap thrills ←→ shape of you ←→ bohemian rhapsody ←→ feels ←→ uptown funk
🌐 Browser Back/Forward

Each webpage visited is a node. Back button follows the prev pointer. Forward button follows the next pointer.

google.com ←→ github.com ←→ stackoverflow.com ↑ current
↩️ Undo/Redo in editors

Each action is a node. Undo moves back, redo moves forward through the linked chain of actions.

🖨️ Print Queue

Print jobs are added dynamically. A linked list handles an unknown number of jobs efficiently.

Section 06

Operations on Singly Linked List (SLL)

① Insert at Beginning

Why: You want to add a new node as the new first node.

Key idea: New node's next must point to the old head. Then head must update to the new node. Do step 1 FIRST — if you update head first, you lose the chain.

1
Create a new node: allocate with malloc, set its data.
2
Set newNode->next = head (new node points to the old first node).
3
Set head = newNode (head now points to the new node).
Before: head → [15] → [7] → [40] → NULL After inserting 5: new → [5] → [15] → [7] → [40] → NULL ↑ head
void insertAtBeginning(struct node **head, int data) {
    struct node *newNode = malloc(sizeof(struct node));
    newNode->data = data;
    newNode->next = *head;   // step 1: link to old head
    *head = newNode;         // step 2: update head
}
⚠ Double Pointer
We use struct node **head (pointer to pointer) so we can change where head points. If you pass just *head, changes won't reflect outside the function.

② Insert at End

Key idea: Walk to the last node (the one whose next == NULL), then attach the new node there.

1
Create new node. Set its data. Set its next = NULL.
2
If list is empty, new node becomes head. Done.
3
Otherwise traverse to the last node (while current->next != NULL).
4
Set lastNode->next = newNode.
void insertAtEnd(struct node **head, int data) {
    struct node *newNode = malloc(sizeof(struct node));
    newNode->data = data;
    newNode->next = NULL;

    if (*head == NULL) { *head = newNode; return; }

    struct node *current = *head;
    while (current->next != NULL)
        current = current->next;   // walk to last node

    current->next = newNode;        // attach new node
}

③ Insert After a Given Node (Middle)

Key idea: You have a pointer to the node AFTER which you want to insert. You must save the current next before overwriting it.

Insert new node after node with value 15: Before: head → [4] → [15] → [7] → [40] → NULL ↑ position node Step 1: newNode->next = position->next // newNode points to [7] Step 2: position->next = newNode // [15] now points to newNode After: head → [4] → [15] → [5] → [7] → [40] → NULL
void insertAfter(struct node *position, int data) {
    struct node *newNode = malloc(sizeof(struct node));
    newNode->data = data;
    newNode->next = position->next;  // preserve the rest of the list
    position->next = newNode;        // link in the new node
}

④ Delete First Node

Key idea: Save head in a temp pointer (so you can free it), then move head forward.

void deleteFirst(struct node **head) {
    if (*head == NULL) return;     // empty list
    struct node *temp = *head;
    *head = (*head)->next;           // move head forward
    free(temp);                     // release the old node
}

⑤ Delete Last Node

Key idea: Walk until you find the second-to-last node (where current->next->next == NULL). Then set its next = NULL and free the last node.

void deleteLast(struct node **head) {
    if (*head == NULL) return;
    if ((*head)->next == NULL) {  // only one node
        free(*head); *head = NULL; return;
    }
    struct node *current = *head;
    while (current->next->next != NULL)  // stop at 2nd-to-last
        current = current->next;
    free(current->next);
    current->next = NULL;
}

⑥ Delete a Middle Node (by value)

Key idea: Walk until you find the node BEFORE the one you want to delete. Then bypass the target node.

Delete node with value 7: head → [4] → [15] → [7] → [40] → NULL ↑ ↑ prev target Step 1: while (head->next->data != 7): walk forward Step 2: temp = head->next // save target Step 3: head->next = head->next->next // bypass target Step 4: free(temp) // release memory After: head → [4] → [15] → [40] → NULL
void deleteMiddle(struct node *head, int value) {
    while (head->next->data != value)
        head = head->next;
    struct node *temp = head->next;
    head->next = head->next->next;
    free(temp);
}
Section 07

Recursion on Linked Lists

The recursive pattern on linked lists is always the same: "Handle the head, then recursively call on the rest."

The rest of the list from the second node is itself a smaller linked list. This is the key insight.

Pattern: Search for a value

struct node* search(struct node *head, int value) {
    if (head == NULL) return NULL;       // base case: not found
    if (head->data == value) return head; // base case: found!
    return search(head->next, value);    // recurse on the rest
}

Recursive Insert at End

The idea: if the list is empty, the new node IS the list. Otherwise, the new node should be attached at the end of the sub-list starting from head->next.

Node* insertRear(Node* l, int data) {
    if (l == NULL) {                     // reached end, create node
        Node *n = createNode(data);
        return n;
    }
    l->next = insertRear(l->next, data); // attach to rest of list
    return l;
}
▶ Python Tutor — insertRear(head, 4) on [1 → 2 → 3 → NULL]  ·  watch each frame return l to rewire the chain on the way back up

Recursive Remove First Occurrence

Node* removeFirst(Node* head, int x) {
    if (head == NULL) return NULL;
    if (head->data == x) {
        Node* tmp = head->next;
        free(head);
        return tmp;            // skip this node
    }
    head->next = removeFirst(head->next, x);
    return head;
}
▶ Python Tutor — removeFirst(head, 2) on [1 → 2 → 3 → NULL]  ·  watch pointer surgery happen on the heap

Recursive Remove ALL Occurrences

Node* removeAll(Node* l, int data) {
    if (l == NULL) return NULL;
    if (l->data == data)
        return removeAll(l->next, data); // skip this, continue
    else {
        l->next = removeAll(l->next, data);
        return l;
    }
}
▶ Python Tutor — removeAll(head, 2) on [1 → 2 → 2 → 3 → NULL]  ·  both 2s get skipped; watch how consecutive matches cascade through the recursion

Pre-order vs Post-order: Where you place the "work" matters

▶ Python Tutor — printForward(head) · print BEFORE recursing → output: 1 2 3
▶ Python Tutor — printReverse(head) · recurse FIRST, then print → output: 3 2 1  ·  watch the stack unwind to reverse the order
✦ The magic recursion pattern
Recursion on linked lists works because head->next is a smaller linked list of the same type. Whatever your function does to a full list, it can do to this smaller list too. The base case is always: what happens when the list is empty (head == NULL)?
Section 08

Reversing a Linked List

This is one of the most famous linked list problems. All arrow directions must flip.

Before: head → [4] → [3] → [5] → [7] → [2] → NULL After: head → [2] → [7] → [5] → [3] → [4] → NULL

Iterative Reversal — 3 Pointer Technique

Use three pointers: prev, current, next. Walk through the list, reversing one arrow at a time.

1
Start: prev = NULL, current = head, next = head->next.
2
Reverse current arrow: current->next = prev
3
Shift all 3 pointers forward: prev = current, current = next, next = next->next
4
Repeat until current is NULL. Then head = prev.
Step by step on [1] → [2] → [3] → NULL: Initially: prev=NULL, curr=[1], next=[2] Step 1: curr->next = NULL → NULL ← [1] [2] → [3] → NULL prev=[1], curr=[2], next=[3] Step 2: curr->next = [1] → NULL ← [1] ← [2] [3] → NULL prev=[2], curr=[3], next=NULL Step 3: curr->next = [2] → NULL ← [1] ← [2] ← [3] prev=[3], curr=NULL → STOP head = prev = [3] ∴ head → [3] → [2] → [1] → NULL ✓
Node* reverseIterative(Node *head) {
    if (head == NULL || head->next == NULL) return head;

    Node* prevP    = NULL;
    Node* currentP = head;
    Node* nextP    = head->next;

    while (currentP) {
        currentP->next = prevP;            // reverse the arrow
        prevP    = currentP;               // shift prev forward
        currentP = nextP;                  // shift current forward
        if (nextP) nextP = nextP->next;   // shift next forward
    }
    return prevP;  // prevP is now the new head
}

Recursive Reversal

Idea: Let recursion reverse the tail first, then fix the head's arrow.

Node* reverseRecursive(Node *head) {
    if (head == NULL || head->next == NULL) return head;

    Node *n = reverseRecursive(head->next); // reverse the rest

    head->next->next = head;  // the old second node now points BACK to head
    head->next = NULL;        // head's old forward link becomes NULL

    return n;                 // n is the new head (last node of original)
}
✦ The magic of head->next->next = head
When recursion returns, head is still pointing forward (old direction). head->next is the node right after head. By doing head->next->next = head, you're making that node point BACK to the current head. This reverses the arrow one step. Then head->next = NULL removes the old forward link.
Section 09

Circular Linked List (CLL)

In a CLL, the last node's next pointer does NOT point to NULL. It points back to the head. The list forms a circle.

head │ ▼ ┌────┬────┐ ┌────┬────┐ ┌────┬────┐ ┌────┬────┐ │ 4 │ ●─┼────>│ 15 │ ●─┼────>│ 7 │ ●─┼────>│ 40 │ ●─┼──┐ └────┴────┘ └────┴────┘ └────┴────┘ └────┴────┘ │ ↑ │ └────────────────────────────────────────────────────────────┘ last node's next = head (not NULL!)

Why CLL?

  • Round-robin scheduling (OS: give each process a time slot, then loop back)
  • Multiplayer board games (player 1 → 2 → 3 → 4 → 1 → ...)
  • Any situation where you continuously cycle through items

Finding Length of CLL

Problem: You cannot check for NULL to stop — there is no NULL. You must stop when you come back to head.

Key trick: Use a do-while loop so you move at least once before checking.

int lengthCLL(struct node *head) {
    if (head == NULL) return 0;
    int result = 0;
    struct node *current = head;
    do {
        current = current->next;
        result++;
    } while (current != head);  // stop when back at head
    return result;
}
⚠ Why do-while and not while?
If you use while(current != head) at the start, the condition is immediately false (current IS head) and you'd return 0. You must move first, then check. That's what do-while does.

Print CLL

void printCLL(Node* front) {
    for (Node *curr = front; curr != front; curr = curr->next)
        printf("%d ", curr->data);
    // wait — this never prints! Same bug as while loop
    // Fix: use do-while or use: curr != NULL && curr != front
}

Insert at End of CLL

1
Create new node. Set its next = NULL.
2
Walk to the last node (the one where current->next == head).
3
Set newNode->next = head (new node completes the circle).
4
Set current->next = newNode (old last node points to new node).

Insert at Beginning of CLL

1
Create new node.
2
Walk to last node (where current->next == head).
3
Set newNode->next = head.
4
Set current->next = newNode (last node now points to new node).
5
Set head = newNode (update head).
Key difference from SLL
In SLL, inserting at beginning is O(1) — just update head and next.
In CLL, inserting at beginning is O(n) — you MUST also update the last node's pointer (otherwise the circle is broken). You must walk to the end to fix it.
Section 10

Doubly Linked List (DLL)

Each node has THREE parts: prev pointer (to previous node), data, and next pointer (to next node).

NULL ←── ┌────┬────┬────┐ ←──── ┌────┬────┬────┐ ←──── ┌────┬────┬────┐ ──→ NULL │prev│ 3 │next│ ─────→ │prev│ 7 │next│ ─────→ │prev│ 5 │next│ └────┴────┴────┘ └────┴────┴────┘ └────┴────┴────┘ ↑ head

DLL allows O(1) traversal in BOTH directions. This is used for:

  • Music players (previous song in O(1))
  • Browser history (go back and forward fast)
  • LRU Cache implementation
struct node {
    struct node *prev;   // points to previous node
    int data;
    struct node *next;   // points to next node
};

Insert at End of DLL

void insertEndDLL(struct node **head, int val) {
    struct node *newNode = malloc(sizeof(struct node));
    newNode->value = val;
    newNode->next  = NULL;
    newNode->prev  = NULL;

    if (*head == NULL) { *head = newNode; return; }

    struct node *current = *head;
    while (current->next != NULL)
        current = current->next;

    current->next  = newNode;   // old last → new node
    newNode->prev  = current;   // new node ← old last
}

Delete a Node in DLL (O(1) with pointer)

If you already have a pointer to the node, deletion is O(1) because you can find both neighbors directly via prev and next.

Delete middle node M: ... [A] ←→ [M] ←→ [B] ... M->prev->next = M->next // A now skips M and points to B M->next->prev = M->prev // B now points back to A free(M) // done! O(1)

Section 12 — The Mental Game

🧠 Pro Thinking — How to Become an Expert

This section rewires how you think about linked list problems. Read it, internalize it, and you will crack problems you have never seen before.

Mental Models to Internalize

🔗 Model 1: "The Chain of Trust"

Every operation depends on the integrity of the chain. If you lose a pointer, you lose all nodes after it. Before any operation, ask: "Will I break the chain? What do I save first?"

Rule: When you want to change a ->next pointer, ALWAYS save the original value first if you will need it later. This is why we always create a temp.

👁️ Model 2: "Two Eyes on the List"

Many problems need TWO pointers moving at different speeds (Slow & Fast pointers). This is how you solve: detect a cycle, find the middle, find the Nth node from the end — all without knowing the length.

Find middle (Slow moves 1 step, Fast moves 2 steps): Slow: [1] → [2] → [3] Fast: [1] → → [3] → → [5] ← Fast is NULL, Slow is middle
📐 Model 3: "Order Matters Critically"

The order in which you set pointers is everything. A wrong order breaks the chain permanently.

Insert after position P: FIRST set newNode->next = P->next. THEN set P->next = newNode. If reversed, you lose all nodes after P.

Delete node N: FIRST bypass it (prev->next = N->next). THEN free(N). Never free first.

🔄 Model 4: "Recursion = Delegate to the Rest"

For recursive problems: "Handle the head, delegate the rest."
What do I do with head right now? → simple logic.
What about everything after head? → recursive call on head->next.
What if list is empty? → your base case (return NULL or 0).

🔃 Model 5: "Reversing = Re-aiming Every Arrow"

When reversing, visualize every arrow (next pointer) flipping direction. You need 3 pointers because: you need to know where you came from (prev), where you are (current), and where you are going (next) — so you don't get lost when you flip the current arrow.

Common Problem Patterns

Problem Type Pattern / Technique
Find middle node Slow/Fast pointer (tortoise & hare)
Detect cycle Slow/Fast pointer — if they meet, cycle exists
Find Nth from end Two pointers, N apart. Move together until first hits NULL.
Reverse a list 3-pointer iterative OR recursive (head->next->next = head)
Merge two sorted lists Compare heads, pick smaller, recurse on rest
Remove duplicates Track current; if current->next == current, skip it
Check palindrome Find middle, reverse second half, compare with first half
Flatten nested list Recursion: flatten sub-list, attach, continue

Edge Case Checklist — Never Miss These

Before submitting any linked list solution, verify your code handles:

Edge Cases to Always Check
  • ✓ Empty list — head == NULL. What happens?
  • ✓ Single node — head->next == NULL. Many algorithms break here.
  • ✓ Two nodes — minimal case for algorithms that look two steps ahead.
  • ✓ All same values — for delete/remove operations.
  • ✓ Target at beginning or end — many solutions forget these edge positions.
  • ✓ Memory leaks — always call free() on deleted nodes.
  • ✓ CLL empty check — head == NULL needed before do-while.

How to Approach Any Linked List Problem

1
Draw it. Always draw the list as boxes and arrows. Draw the before and after state you want. Never code before drawing. Most bugs come from skipping this step.
2
Identify what pointers you need. Do you need one pointer? Two? A prev and current? Write them down before coding.
3
Decide the order of pointer changes. Write the steps in English first: "First save X, then point A to B, then update head." Order matters critically.
4
Test on a 3-4 node list by hand. Trace through your code mentally with a small example. Catch bugs before running.
5
Test edge cases. Run your mental trace with: empty list, 1 node, 2 nodes, target at beginning, target at end.

Key Insights That Separate Beginners from Experts

💡 Insight 1: Linked lists shine at FRONT operations

Insert/delete at front is O(1) — the fastest possible. If your problem needs a queue (FIFO) or stack (LIFO), think linked list. Array-based stacks/queues require shifting or resizing.

💡 Insight 2: The "dummy head" trick

Many problems have ugly edge cases for the first node. Create a dummy node before head: struct node dummy; dummy.next = head;. Now all nodes including the first are treated uniformly. Remove dummy at the end.

💡 Insight 3: Returning the head from recursive functions

When your function modifies the list recursively, always return the (possibly new) head. The pattern is: head->next = recursive_call(head->next); return head;. This chains the modifications correctly without needing a double pointer.

💡 Insight 4: CLL and DLL are just SLL with extra pointers

Don't think of them as completely different. CLL = SLL where last->next = head instead of NULL. DLL = SLL where each node also has a prev pointer. Every new pointer means extra work to keep it consistent — but also new capabilities.

💡 Insight 5: When in doubt, count your pointer operations

If you change K pointers in an insert, check all K are still valid after each change. If any pointer assignment could leave a node unreachable, you have a bug. Think of it like renaming a street — you must update ALL signs that reference it.

Quick Reference Patterns

// Empty check:
if (head == NULL) ...

// Single node check:
if (head->next == NULL) ...

// Walk to last node (SLL):
while (current->next != NULL) current = current->next;

// Walk to last node (CLL):
while (current->next != head) current = current->next;

// Walk to 2nd-to-last (for delete last):
while (current->next->next != NULL) current = current->next;

// Slow/Fast pointer setup:
Node *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
} // slow is now at middle

// Standard recursive template:
ReturnType func(Node *head) {
    if (head == NULL) return BASE_CASE;
    // do something with head
    func(head->next);
}
Final Advice
The best way to become a pro is to implement all operations from scratch, on paper, without looking at notes. Then verify. The act of making mistakes and fixing them builds the intuition that no amount of reading can give you. Every pointer bug you fix is a lesson you will never forget.
