Binary Trees & BST

The Big Picture

A Binary Tree is a hierarchical structure where every node has at most 2 children (left, right). It is a foundation for almost all advanced data structures.

The learning journey follows a natural progression:

A Binary Search Tree (BST) adds an ordering property so we can search efficiently. BST is the prerequisite for AVL trees, heaps, and hashing.

Part 1

Binary Tree – Fundamentals

What is a Binary Tree?
Definition

A binary tree is a tree where every node has at most 2 children — a left child and a right child. Nodes can have 0, 1, or 2 children. A node with 3 or more children is not a binary tree.

Types: Full, Complete, Perfect
🌳 Full Binary Tree

Rule: Every node has 0 or 2 children. No node can have exactly 1 child.

Think: internal nodes are always "full" (both seats taken or none).

✅ Complete Binary Tree

Rule: All levels are completely full except the last level, and the last level is filled from left to right (no gaps in the middle).

Think: you fill like reading — left to right, top to bottom, no skipping.

⭐ Perfect Binary Tree

Rule: Every level is completely full. It is both Full AND Complete. No more nodes can be added without increasing height.

⚠️ Author Warning

Some authors use "complete" to mean what others call "perfect". The IIT/GATE convention used here: Complete = last level left-filled, Perfect = all levels full. Always check what the question means!

Depth & Height
Depth (= Level)

Defined for a node.
Number of edges from root to that node.
Root has depth 0.

Think: standing at the surface, looking down into a well.

Height

Defined for a node OR tree.
Number of edges in the longest path from that node to a leaf.
Leaf has height 0. Height of tree = height of root.

Think: measuring how tall a building is — from bottom up.

💡 Key Insight

Height is computed bottom-up: start from leaves (h=0), then work upward. height(node) = max(height(left), height(right)) + 1

Key Formulas & Relations
General Binary Tree — Leaf vs Degree-2 Relation
🔑 Magic Relation (any binary tree)

In any binary tree:

L = N₂ + 1
// L = number of leaf nodes, N₂ = nodes with exactly 2 children

Why it works: Every time you add a degree-2 node, you automatically add a leaf. They increase together in lock-step. This starts with L=1, N₂=0 (single node) and holds for every addition.

Full Binary Tree — Additional Relations

In a full binary tree, every internal node has exactly 2 children. So internal nodes = degree-2 nodes.

L = I + 1   // L = leaves, I = internal nodes
N = L + I = 2I + 1   // total nodes

// Level i has exactly:

// Minimum nodes (last level has just 1 node):

// Maximum nodes (last level is full = perfect tree):

// Minimum (skewed tree — one path down):
N_min = h + 1

// Maximum (perfect tree):
N_max = 2h+1 - 1

// Height range for N nodes:
log₂(N+1)-1 ≤ h ≤ N-1
// ← best case (balanced) & worst case (skewed)
Representations: Array & Linked List
Array Representation (only for Complete Binary Trees)
How it works

Store nodes level by level, left to right, starting at index 1 (1-indexed).

This works only for complete binary trees because every level is full — no need to store NULL placeholders.

// For node at index i (1-indexed):
Parent = i / 2
Left child = 2i
Right child = 2i + 1

// If 0-indexed (GATE question): parent of i = ⌊(i-1)/2⌋
🎯 GATE 2014 Tricky Question

Q: An array is a complete binary tree, starting index 0. What is the index of the parent of element at index i?

Method: Pretend index is 1-based (shift by +1), use ⌊(i+1)/2⌋, then shift back: ⌊(i+1)/2⌋ - 1. This equals ⌊(i-1)/2⌋.

Answer: ⌊(i-1)/2⌋ — just test with example: i=6, parent should be index 2 → (6-1)/2 = 2 ✓

Linked List (Pointer) Representation — General & Universal
struct Node {
    int data;
    struct Node *left;   // pointer to left child
    struct Node *right;  // pointer to right child
};

// Creating a root node:
struct Node *root = malloc(sizeof(struct Node));
root->data  = 5;
root->left  = NULL;
root->right = NULL;

// Adding left child:
root->left = malloc(sizeof(struct Node));
root->left->data  = 3;
root->left->left  = NULL;
root->left->right = NULL;

Works for any binary tree. Same idea as a doubly linked list, but instead of prev/next we say left/right.

Part 2

Tree Traversals

Pre-order, In-order, Post-order

A traversal is a way to visit every node exactly once. There are 3 main traversals based on when you visit the root relative to left and right subtrees:

The 3 Traversals — One Rule Each
NameOrderMemory trick
Pre-orderRoot → Left → RightRoot comes before children
In-orderLeft → Root → RightRoot is in between children
Post-orderLeft → Right → RootRoot comes after children
// Preorder
void preorder(Node *t) {
    if (!t) return;
    print(t->data);   // ROOT first
    preorder(t->left);
    preorder(t->right);
}

// Inorder
void inorder(Node *t) {
    if (!t) return;
    inorder(t->left);
    print(t->data);   // ROOT in middle
    inorder(t->right);
}

// Postorder
void postorder(Node *t) {
    if (!t) return;
    postorder(t->left);
    postorder(t->right);
    print(t->data);   // ROOT last
}
Technique 1: Fill-in-Blanks Method

For a tree with n nodes, make n blank slots for each traversal type, then fill recursively:

📝 Worked Example — Tree: A(B(D,E), C(F,G))
TraversalResultHow
Pre-orderA, B, D, E, C, F, GRoot(A), Left(BDE), Right(CFG)
In-orderD, B, E, A, F, C, GLeft(D), Root(B), Right(E)... project!
Post-orderD, E, B, F, G, C, ALeft(DE), Right(FG), Root last
Technique 2: Traversal Trick (visit-count method)
The Trick

Draw the tree. Add two null lines at every leaf (both children = null). Then walk around the tree, touching every node multiple times:

  • 1st visit → print in Pre-order
  • 2nd visit → print in In-order
  • 3rd visit → print in Post-order
In-order Projection Trick (for BST — Visual only)

For BST only, in-order = sorted order. You can literally project the nodes vertically onto a number line — left to right gives in-order sequence. Very useful for visualization.

Tree Construction from Traversals
🔑 The Core Algorithm
Find the root — Pre-order: first element. Post-order: last element.
Find root in in-order — everything left = left subtree, everything right = right subtree.
Recurse — apply same steps to left and right subtree sequences.
📝 Example: In-order + Pre-order → Unique Tree

In-order: G D H B E A F J C  |  Pre-order: A B D G H E C F J

Pre-order: A is root.
In A's in-order position: left = {G,D,H,B,E}, right = {F,J,C}
From pre-order left group {B,D,G,H,E}: B is root of left subtree.
B's in-order: left={G,D,H}, right={E}. Continue recursively...
📊 Uniqueness Summary Table
Tree TypeTraversals Needed for Unique Tree
General Binary TreeIn-order MUST be given + either Pre-order or Post-order
Full Binary TreeAny 2 (Pre+Post also works, unlike general)
Complete Binary TreeJust 1 traversal is enough (map to structure)
Given only Pre-order / only Post-order / only In-order (general)Multiple trees possible — Catalan number = C(n) possibilities
💡 Full BT from Pre+Post (Key Step)

After finding the root (first of pre), find the second element of pre — that's the root of the LEFT subtree. Find it in post-order: everything before it in post = left subtree nodes. This uniquely determines the split because full BT has no 1-child nodes.

Code Analysis (GATE-Style)
Pattern Recognition: What does the function do?
🔑 Strategy for Code Analysis
  1. Look at the base case — what does it return for leaves/null?
  2. Look at what it does with left and right — sum? max? compare?
  3. Eliminate options — if it takes MAX of left & right, it cannot be computing "total nodes/leaves" (those need SUM).
  4. Trace with a small example to confirm.
📝 Classic Example 1 — Find what this returns
int fun(Node *t) {
    if (!t) return -1;                      // null → -1
    if (!t->left && !t->right) return 0;  // leaf → 0
    int a = (t->left)  ? fun(t->left)  : -1;
    int b = (t->right) ? fun(t->right) : -1;
    return max(a, b) + 1;                    // max child height + 1
}

Answer: Height of the tree. Leaf returns 0, each node returns max-child-height + 1. Taking MAX means it follows the longest path = height definition.

📝 Classic Example 2 — Mirror Image
void dodo(Node *t) {
    if (!t) return;
    dodo(t->left);
    dodo(t->right);
    Node *temp = t->left;   // swap left and right
    t->left = t->right;
    t->right = temp;
}

Answer: Creates mirror image of the tree (reflects all left↔right pointers). First recurses deep, then swaps on the way back up (post-order).

📝 Classic Example 3 — Compare two trees
int checkSame(Node *r1, Node *r2) {
    if (!r1 && !r2) return 1;    // both null → same ✓
    if (!r1 || !r2) return 0;    // one null, one not → different ✗
    return (r1->data == r2->data)  // data same AND
        && checkSame(r1->left, r2->left)   // left subtrees same AND
        && checkSame(r1->right, r2->right); // right subtrees same
}

// If data check is removed → only checks structural equality
📝 Classic Example 4 — Level-order (BFS) Deepest Node
checkD(root):
  if root == null: return null
  enqueue(root)
  while Q not empty:
    temp = dequeue()
    if temp.left:  enqueue(temp.left)
    if temp.right: enqueue(temp.right)
  return temp   // last dequeued = deepest node

Answer: Returns the deepest (last level) node. BFS visits level by level; the last dequeued element is deepest.

Part 3

Binary Search Tree (BST)

What is a BST?
The BST Property (applied to EVERY node)

For any node with value X:

  • All values in the LEFT subtree are < X
  • All values in the RIGHT subtree are > X

This must hold recursively for every node, not just the root!

⚡ Magic Property of BST

In-order traversal of a BST is always sorted (increasing order).

Think: project BST nodes onto a number line — they appear in order. That's the in-order!

Search in BST
Algorithm
Start at root. Compare search key with current node value.
If equal → Found!
If key < current → go LEFT (smaller values are there)
If key > current → go RIGHT (larger values are there)
If reach NULL → Not Found

Insert & Build a BST

Insertion is like search — follow the BST property to find where the new value should be, then add a leaf node there.

📝 Build BST from sequence: 10, 12, 5, 4, 20, 8, 7, 15, 13
InsertPath taken
10Root (tree empty)
1212 > 10 → go right. Place here.
55 < 10 → go left. Place here.
44 < 10 → left, 4 < 5 → left. Place here.
2020 > 10 → right, 20 > 12 → right. Place here.
88 < 10 → left, 8 > 5 → right. Place here.
77 < 10 → left, 7 > 5 → right, 7 < 8 → left. Place here.
Deletion in BST — 3 Cases
Case 1: Leaf node Case 2: One child Case 3: Two children
Case 1 — Delete a Leaf Node

Simplest case. Just remove it. No restructuring needed.

Example: Delete 7 from the BST above → just remove the node. Done.

Case 2 — Delete Node with ONE Child

Remove the node and connect its parent directly to its only child.

Think: bypass the node like a bridge over a gap.

parent → node → child   becomes   parent → child
Case 3 — Delete Node with TWO Children (Key idea!)

You cannot just remove it (two children fight for the spot). Instead:

Find the In-order Predecessor (max of left subtree) OR In-order Successor (min of right subtree).
Replace the node's value with the predecessor/successor value.
Delete the predecessor/successor from its original location. This is now either Case 1 or Case 2 (never Case 3 again — see why below).
🧠 Why Can't It Be Case 3 Again?

The in-order predecessor is the maximum of the left subtree → found by going right until no right child → it has no right child. So at most 1 child (the left). Similarly for successor.

📝 Example: Delete node 10 (root, 2 children)
Node 10 has two children (5 and 12).
In-order predecessor = max of left subtree(5) = 8 (go right from 5 → 8 → no more right).
Replace 10 with 8 → root becomes 8.
Now delete 8 from its old position. It has only left child (7) → Case 2! Connect 5's right to 7.
In-order Predecessor & Successor
Definitions

Predecessor of X: the value printed just before X in in-order traversal = maximum value in X's left subtree.

Successor of X: the value printed just after X in in-order traversal = minimum value in X's right subtree.

⚠️ Common Mistake

Predecessor/Successor can exist even when left/right subtree is missing! Always take the in-order and look before/after X. E.g., if X has no left subtree, its predecessor could be an ancestor node.

Min, Max, kth element, Range Search
Find Minimum

Keep going LEFT until you can't. The leftmost node = minimum.

Find Maximum

Keep going RIGHT until you can't. The rightmost node = maximum.

kth Minimum / Maximum

Take the in-order of the BST (it's sorted!). The kth element in this sorted list is the answer. Time: Θ(n) since in-order takes O(n).

Range Search — Find all nodes in [k1, k2]
Algorithm
At each node, check if value is inside [k1, k2], below k1, or above k2.
Inside range: process this node, then search BOTH left AND right subtrees.
Below k1: go RIGHT only (need bigger values).
Above k2: go LEFT only (need smaller values).
void rangePrint(Node *root, int k1, int k2) {
    if (!root) return;
    if (root->data >= k1 && root->data <= k2) {
        print(root->data);         // in range: print
        rangePrint(root->left,  k1, k2);  // search both sides
        rangePrint(root->right, k1, k2);
    } else if (root->data < k1) {
        rangePrint(root->right, k1, k2);  // too small: go right
    } else {
        rangePrint(root->left,  k1, k2);  // too big: go left
    }
}
Time Complexity of Range Search

Let k = number of nodes in the range, h = height of BST.

T = O(k + h)
// k nodes are in range (must visit all)
// At most 2 "border" paths, each of length h (just the boundary nodes)
// O(k + h) because in worst case, range is tiny but we travel h levels to find it

The 2h "border" nodes are the nodes at the edge of the search that are outside your range but still visited. They can overlap with k, so the bound is tight at O(k+h).

BST Time Complexity
Best / Worst / Average Cases — Definitions

Best case: Input that gives minimum time (even one such input counts).

Worst case: Input that gives maximum time (even one such input counts).

Average case: Average time over all possible inputs (weighted by probability).

In data structures, "input" = (the state of the data structure) + (the element to operate on).

OperationBest CaseWorst CaseAverage Case
SearchO(1) — root is targetO(n) — skewed tree, search leafO(log n)
InsertO(1) — insert as root's childO(n) — skewed treeO(log n)
DeleteO(1) — delete root's child (leaf)O(n) — skewed treeO(log n)
In-order traversalΘ(n)Θ(n)Θ(n)
kth min/maxO(1)O(n)O(log n)
Range search [k1,k2]O(1)O(k+h)O(k+h)
⚠️ The BST Worst Case Problem

If you insert nodes in sorted order (e.g., 1, 2, 3, 4, 5...), the BST degrades into a skewed tree (like a linked list). Height becomes O(n), so all operations become O(n). This is why we need balanced BSTs like AVL trees!

Solution: AVL Trees (self-balancing BST) — they maintain O(log n) height always.

⚡ Quick Revision Notes

Binary Tree — Types

Full BT: every node has 0 or 2 children (no 1-child nodes)
Complete BT: all levels full except last; last level left-filled
Perfect BT: every level completely full (also full & complete)
Depth: edges from ROOT to node (root=0)
Height: edges from node to deepest LEAF below it (leaf=0)

Key Formulas

Any BT: L = N₂ + 1 (leaves = degree-2 nodes + 1)
Full BT: L = I + 1, N = 2I + 1
Perfect BT (h): L=2ʰ, I=2ʰ-1, N=2ʰ⁺¹-1
Level i in perfect BT: 2ⁱ nodes
Complete BT (h): min nodes = 2ʰ, max = 2ʰ⁺¹-1
General BT (h): min nodes = h+1, max = 2ʰ⁺¹-1
Height range (N nodes): ⌊log₂N⌋ ≤ h ≤ N-1

Array Representation

Only for complete BT. Index from 1.
Parent(i) = i/2, Left(i) = 2i, Right(i) = 2i+1
0-indexed: Parent(i) = ⌊(i-1)/2⌋

Traversals

Pre-order: Root → L → R
In-order: L → Root → R (projection on number line)
Post-order: L → R → Root
All traversals: Θ(n) time
Trick: walk tree, 1st visit=pre, 2nd=in, 3rd=post

Tree Construction Uniqueness

General BT: in-order + (pre or post) → unique
Full BT: any 2 traversals → unique (pre+post also works!)
Complete BT: just 1 traversal → unique (fill the structure)
Only pre-order or only post-order (general) → Catalan number of trees

BST Property

Left subtree values < node; right subtree values > node (recursive)
In-order of BST = sorted sequence (magic!)
Find min: go left until null. Find max: go right until null.
kth min/max: take in-order, pick kth element. O(n)

BST Operations

Search/Insert: compare, go left or right. O(h).
Delete Case 1: leaf → just remove
Delete Case 2: 1 child → link parent to child
Delete Case 3: 2 children → replace with in-order predecessor (max of left) or successor (min of right), then delete that → becomes Case 1 or 2
In-order predecessor: max of left subtree
In-order successor: min of right subtree

BST Time Complexity

Worst (skewed): O(n) for search/insert/delete
Best (balanced): O(log n)
Average: O(log n)
Range search: O(k + h) where k=nodes in range, h=height
Skewed tree arises when inserting sorted data → need AVL trees!

Code Analysis Patterns

Returns MAX of subtrees + 1 → Height
Returns SUM of subtrees → counting something (total nodes etc)
Swaps left/right pointers → Mirror image
Compares two trees node by node → Equality check
BFS (queue), returns last dequeued → Deepest node
Leaf returns 0 or 1; no recursion at leaf → base case of height/count
