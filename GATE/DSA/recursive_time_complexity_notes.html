01

Why Study Time Complexity?

The Problem

When a program runs, two questions arise:

"Why is my program so slow?" → Time Complexity
"Why does it run out of memory?" → Space Complexity (very easy, not focus here)

We cannot just use a stopwatch — the time depends on your specific computer, current load, etc. We need a mathematical method that works for any machine.

The key insight (Knuth, 1970s): Use the scientific method — model the program mathematically and analyze the model.

Why Recursive Programs Are Tricky

For a simple loop like for(i=0; i<n; i++), counting steps is straightforward. But recursive programs call themselves with a smaller input, so the time T(n) depends on T(smaller n). That self-referential nature needs a special math tool.

A recurrence relation is that special tool — an equation where T(n) is defined in terms of T(smaller).

Writing Recurrence Relations

What is a Recurrence Relation?

It is a math equation that says: "the time to solve problem of size n = time to solve smaller subproblems + extra work done now."

T(n) = T(n-1) + 1 ← call myself with n-1, then do 1 unit of work T(n) = T(n/2) + 1 ← call myself with n/2, then do 1 unit of work T(n) = 2T(n/2) + n ← call myself TWICE with n/2, then do n work (Merge Sort!)

Step-by-Step: How to Write a Recurrence from Code

  • 1
    Look at the recursive call(s). What input is passed? → This tells you T(what).
  • 2
    Count how many recursive calls are made. → This is the multiplier in front.
  • 3
    Count work done outside the recursion (comparisons, loops, assignments). → This is the extra term.
  • 4
    Write the base case: T(1) = 1 or T(0) = 1 — when recursion stops.

Example A — Simple Linear Recursion

fun(n) {
  if (n <= 1) return 1;      // base case: T(1) = 1
  else return fun(n/2);       // 1 call with n/2, no extra work
}
T(n) = T(n/2) + 1, T(1) = 1

Example B — Accumulator Recursion

A(n) {
  if (n <= 1) return 1;
  else return A(n-1) + n;     // 1 call with n-1, plus 1 unit (the +n)
}
T(n) = T(n-1) + 1, T(1) = 1 // Note: the "+n" inside A(n-1)+n is just 1 operation, not n operations

Example C — Two Recursive Calls

fun(n) {
  fun(n/2);          // call 1
  fun(n/2);          // call 2  → 2 calls, each with n/2
  // no extra loop   // extra work = 1
}
T(n) = 2T(n/2) + 1
The "+n" in A(n-1)+n is just ONE arithmetic operation. Don't confuse the mathematical value with the count of operations.

The Objective

Given a recurrence like T(n) = T(n/2) + 1, find a closed-form expression (no T on the right side). That closed form tells us exactly how the algorithm scales with input size n.

We are doing approximation, not exact discrete math. So n·log(n) + n ≈ n·log(n) (ignore smaller terms).

Iteration Method (Repeated Substitution)

Purpose & Big Idea

Goal: Turn a recurrence into a simple formula by substituting the same recurrence into itself, over and over, until a pattern appears.

The magic idea: Keep expanding T(smaller) using the same rule, and you'll see a pattern after 2–3 steps. Generalize that pattern to the k-th step, then find k by setting the base case.

How to Do It — 4 Steps

  • 1
    Expand T(n) once using the given rule.
    Substitute the recurrence into itself one time.
  • 2
    Expand again (expand the inner T).
    Now you have T(n-2) or T(n/4) etc. — one more level.
  • 3
    Observe the pattern after 2–3 steps → write it for general step k.
    Don't add terms — observe the series!
  • 4
    Find k by setting the argument equal to the base case value (1 or 0).
    This tells you when the recursion stops.
Example 1 Easy — T(n) = T(n−1) + 1, T(1) = 1

This code: a function that calls itself with n-1 and does 1 unit of work each time.

Step 1: Write the recurrence T(n) = T(n-1) + 1 ← original Step 2: Expand T(n-1) using the same rule: T(n-1) = T(n-2)+1 T(n) = [T(n-2) + 1] + 1 = T(n-2) + 2 Step 3: Expand T(n-2) → T(n-3)+1 T(n) = T(n-3) + 3 Step 4: See the pattern! After k expansions: T(n) = T(n-k) + k Step 5: Stop when argument = 1 → n-k = 1 → k = n-1 T(n) = T(1) + (n-1) = 1 + n - 1 = n = Θ(n)
The argument of T decreases by 1 each step → k = n−1 steps total → linear time.
Example 2 Medium — T(n) = T(n−1) + n, T(1) = 1

Like Example 1, but the extra work is n (not 1). This is like adding 1+2+3+...+n.

T(n) = T(n-1) + n = T(n-2) + (n-1) + n ← expand T(n-1) = T(n-3) + (n-2) + (n-1) + n ← expand T(n-2) ... = T(n-k) + (n-k+1) + ... + n Stop when n-k = 1 → k = n-1: T(n) = T(1) + 2 + 3 + ... + n = 1 + (2+3+...+n) = n(n+1)/2 = Θ(n²)
Key observation: the extra terms form the arithmetic series 1+2+3+...+n = n(n+1)/2.
Example 3 Medium — T(n) = T(n/2) + n, T(1) = 1

The argument halves each step. Extra work is n (a decreasing geometric series).

T(n) = T(n/2) + n = T(n/4) + n/2 + n ← expand T(n/2) = T(n/4) + n/2 = T(n/8) + n/4 + n/2 + n ... = T(n/2ᵏ) + n[1 + 1/2 + 1/4 + ... + 1/2ᵏ⁻¹] Stop when n/2ᵏ = 1 → 2ᵏ = n → k = log₂n Sum = n · [geometric series with r=1/2] = n · 2(1 - 1/n) ≈ 2n - 1 = O(n) The series 1 + 1/2 + 1/4 + ... → 2 (constant), so T(n) = O(n)
Magic: even though we call T(n/2), the decreasing geometric series sums to a constant → total is just O(n)!
Example 4 Hard — T(n) = 2T(n/2) + n·log n
T(n) = 2T(n/2) + n·log n = 2[2T(n/4) + (n/2)·log(n/2)] + n·log n = 4T(n/4) + 2·(n/2)·log(n/2) + n·log n = 4T(n/4) + n·log(n/2) + n·log n After k steps: T(n) = 2ᵏ·T(n/2ᵏ) + n[log(n/2ᵏ⁻¹)+...+log n] When k=log n: n·(something involving log²n) Result: Θ(n log² n)
This one is tricky. The iteration method can get messy. Recursion Tree is cleaner here.
Example 5 — Classic T(n) = 2T(n/2) + n (Merge Sort)
T(n) = 2T(n/2) + n = 2[2T(n/4) + n/2] + n = 4T(n/4) + n + n = 4[2T(n/8) + n/4] + n + n = 8T(n/8) + n + n + n ... = 2ⁱ·T(n/2ⁱ) + i·n Stop when n/2ⁱ = 1 → i = log n: T(n) = n·T(1) + n·log n = n + n·log n = Θ(n log n)
Each level contributes exactly n work. There are log n levels. Total = n log n.
Example 6 — Tricky T(n) = √n · T(√n) + n

The argument is √n and there are √n calls. The trick: substitute n = 2m to simplify.

Let n = 2ᵐ, so √n = 2^(m/2), and define S(m) = T(2ᵐ)/2ᵐ After substitution: S(m) = S(m/2) + 1 → Θ(log m) Back-substitute: m = log n, so S(log n) = Θ(log log n) T(n) = n · S(m) ≈ n · Θ(log log n) = Θ(n log log n)
When T(n) involves √n as both multiplier and argument, substitute n = 2^m to convert it into a simpler recurrence.

Useful Series for Summation

Arithmetic: 1 + 2 + 3 + ... + n = n(n+1)/2 = Θ(n²) Geometric (r < 1): 1 + r + r² + ... → 1/(1-r) = constant = Θ(1) Geometric (r = 1): each term same → Θ(n) terms Geometric (r > 1): last term dominates → Θ(rⁿ) Shortcut rule for 1 + c + c² + ... + cⁿ: if c < 1 → Θ(1) ← first term dominates if c = 1 → Θ(n) ← all terms equal if c > 1 → Θ(cⁿ) ← last term dominates

Recursion Tree Method

Purpose & Big Idea

Instead of algebra, draw a tree. Each node is a subproblem. The cost of each node is the work done at that level (excluding recursive calls). Sum all node costs = T(n).

This method is visual and great for getting bounds (lower and upper), especially when branches have unequal sizes.

Step-by-Step Process

  • 1
    Draw the root node with cost = the non-recursive part of T(n). Example: T(n) = T(n/5) + T(4n/5) + n → root cost is n.
    The root is the "current" call — it does n work before passing to children.
  • 2
    Draw children: one child for each recursive call. Label each child with the argument it receives (n/5 and 4n/5).
    Children represent the recursive calls.
  • 3
    At each child node, write its cost = (non-recursive part of T at that smaller input).
    Each level's costs come from substituting the argument into f(n).
  • 4
    Repeat until leaves. Leaves have cost T(1) = 1.
    Base case is where recursion stops.
  • 5
    Sum all costs row by row (level by level). Then sum across levels.
    Total cost = sum of all work done at all levels.
Example 7 — Unequal Branches T(n) = T(n/5) + T(4n/5) + n

Two branches of different sizes: one shrinks fast (n/5), one shrinks slow (4n/5). This gives a different depth on left vs right.

Level 0: n Level 1: n/5 + 4n/5 = n Level 2: (n/5)² + 2·(n/5)(4n/5) + (4n/5)² = n → Every level sums to exactly n! Lower bound (shortest branch = log₅ n levels): T(n) ≥ n·log₅ n = Ω(n·log n) Upper bound (longest branch = log₅/₄ n levels): T(n) ≤ n·log_{5/4} n = O(n·log n) Since lower = upper (both are n·logn with different constants): T(n) = Θ(n log n)
When every level sums to the same value (n in this case), the total is n × (number of levels). The number of levels is log(n) in some base.
Example 8 — Asymmetric T(n) = T(n/3) + T(2n/3) + n
Level costs: n → n → n → ... (each level sums to n) Shortest branch depth: log₃ n (the n/3 branch hits 1 faster) Longest branch depth: log_{3/2} n (the 2n/3 branch) Lower bound: n · log₃ n → Ω(n log n) Upper bound: n · log_{3/2} n → O(n log n) T(n) = Θ(n log n) (same big-picture answer, different constants)
Example 9 — Fibonacci-like T(n) = T(n−1) + T(n−2) + 1
Tree depth: n levels (argument decreases by 1 each step) Nodes at level k: 2ᵏ potential nodes (binary tree) BUT: right branch (n-2) is shallower than left (n-1) Lower bound (right branch, depth ~n/2): sum = 2⁰+2¹+...+2^(n/2) = 2^(n/2) Upper bound (left branch, depth n): sum = 2⁰+2¹+...+2ⁿ = 2ⁿ → T(n) = Ω(2^(n/2)) and T(n) = O(2ⁿ) → Θ cannot be determined simply (Θ = actual ≈ φⁿ where φ = golden ratio ≈ 1.618) Key insight: T(n) = Θ(2^(n/2)) ≤ T(n) ≤ O(2ⁿ)
Important: Θ cannot tighten the bound here to Θ — only Ω and O. This shows a limitation of the tree method for some recurrences.
Example 10 — Three Branches T(n) = T(n/2) + T(n/3) + T(n/4) + 1
Level 0 cost: 1 (root) Level 1: 3 nodes → cost 3 Level 2: up to 9 nodes → cost changes per branch... Lower bound (fastest-dying branch = n/2 path only): depth ≈ log₂ n, right branch never survives → ~log₂ n levels with 1 node each → Ω(log n) ... but we have 3 branches → Ω(n) approximately Upper bound (slowest-dying branch = n/2 path, but 3ᵏ nodes at level k): depth = log₂ n, 3ᵏ nodes → 3^(log₂ n) = n^(log₂ 3) ≈ n^1.58 → O(n^1.58) T(n) = Θ(n) approximately [practical answer: sub-linear to linear]
The three-branch case is complex. The key is that n/2+n/3+n/4 = 13n/12 > n, but only barely. The answer is close to linear.

Master Theorem — The Quick Formula

Purpose

The Master Theorem is a "lookup table" for recurrences of the specific form T(n) = aT(n/b) + f(n). Instead of doing algebra, you just compare f(n) with n^(log_b a) and apply the matching case.

Applies only when: a ≥ 1 (integer), b > 1, and f(n) is an asymptotically positive function.

The 3 Cases

The "battle" is between: f(n) (work done at current level) vs n^(log_b a) (total work done at leaf level).

1
If f(n) = O(n^(log_b(a) − ε)) for some ε > 0
T(n) = Θ(n^(log_b a))
f(n) is polynomially SMALLER than n^(log_b a) → leaves dominate → answer is leaf cost
2
If f(n) = Θ(n^(log_b a)) (polynomially equal)
T(n) = Θ(n^(log_b a) · log n)
Both tied → each level costs the same → multiply by number of levels (log n)
3
If f(n) = Ω(n^(log_b(a) + ε)) for some ε > 0
T(n) = Θ(f(n))
f(n) is polynomially LARGER than n^(log_b a) → root dominates → answer is root cost

What Does "Polynomially Greater" Mean?

This is the key nuance! "Polynomially greater" means there exists ε > 0 such that f(n) / n^(log_b a) → ∞ fast enough.

ComparisonPolynomially Greater?Reason
n³ vs n²YESn³/n² = n → ∞ polynomially
n³ log n vs n²YESn³ log n / n² = n log n → ∞
n² log n vs n²NOn² log n / n² = log n → ∞ but NOT polynomial
n log n vs nNOlog n grows too slowly — NOT a polynomial factor
2ⁿ vs n^kYESexponential always beats polynomial
n^0.5 vs nNOn^0.5 / n = n^(-0.5) → 0, so n^0.5 is SMALLER, not larger
n² log n is NOT polynomially greater than n². The log factor is too slow. Master Theorem CANNOT be applied when the difference is only a log factor!
Master Theorem Examples Various Cases

E1: T(n) = 9T(n/3) + n → Case 1

a=9, b=3, f(n)=n n^(log₃9) = n^(log₃3²) = n² f(n) = n vs n² → f is polynomially SMALLER (n < n², since n/n² = 1/n → 0) → Case 1: T(n) = Θ(n²)

E2: T(n) = 4T(n/2) + n² → Case 2

a=4, b=2, f(n)=n² n^(log₂4) = n² f(n) = n² = n^(log₂4) → EQUAL (polynomially equal) → Case 2: T(n) = Θ(n² log n)

E3: T(n) = 3T(n/4) + n·log n → Case 3

a=3, b=4, f(n)=n·log n n^(log₄3) = n^0.79... f(n) = n·log n vs n^0.79 → f is polynomially LARGER (n > n^0.79) → Case 3: T(n) = Θ(n log n)

E4: T(n) = 8T(n/2) + n² → Case 1

a=8, b=2, f(n)=n² n^(log₂8) = n³ f(n) = n² vs n³ → f is polynomially SMALLER → Case 1: T(n) = Θ(n³)

E5: T(n) = 2T(n/2) + n·log n → CANNOT APPLY

a=2, b=2, f(n)=n·log n n^(log₂2) = n¹ = n f(n) = n·log n vs n → difference is log n factor log n is NOT a polynomial difference (no ε > 0 such that n·log n = Ω(n^(1+ε))) → Master Theorem CANNOT be applied! Use Iteration or Tree method. // Answer by iteration: Θ(n log² n)

E6: T(n) = T(n/2) + 2ⁿ → Case 3

a=1, b=2, f(n)=2ⁿ n^(log₂1) = n⁰ = 1 f(n) = 2ⁿ vs 1 → 2ⁿ is exponentially/polynomially LARGER → Case 3: T(n) = Θ(2ⁿ)

E7: T(n) = T(n/2) + √n → Case 3

a=1, b=2, f(n)=√n = n^0.5 n^(log₂1) = n⁰ = 1 f(n) = n^0.5 vs 1 → polynomially LARGER (ε=0.5) → Case 3: T(n) = Θ(√n)

E8 (Tricky): T(n) = 2T(n/3) + (lg n)² → Case 1

a=2, b=3, f(n)=(log n)² n^(log₃2) = n^0.631 f(n) = (log n)² vs n^0.631 Is (log n)² polynomially smaller than n^0.631? → Yes! n^0.631 grows much faster than (log n)² for large n. (log n)² / n^0.631 → 0 as n→∞, and there's more than log difference → Case 1: T(n) = Θ(n^(log₃2)) = Θ(n^0.631)

Limitations & What Comes Next

Limitations of Each Method

MethodLimitationWhen It Fails
Iteration Can get algebraically complex Multiple recursive calls with unequal sizes
Recursion Tree Only gives bounds; might not tighten to Θ Fibonacci-like recurrences with decreasing arguments
Master Theorem Only works for exact form T(n)=aT(n/b)+f(n) Unequal splits like T(n/3)+T(2n/3); when difference is only log factor

Master Theorem — Cannot Apply Cases

These are common traps in exams!
  • ✗
    T(n) = 2T(n/2) + n log n — f(n) = n log n is NOT polynomially greater than n (difference is only log n). Use iteration → Θ(n log²n).
  • ✗
    T(n) = 4T(n/2) + n² log n — n² log n is NOT polynomially greater than n² (difference is only log n). Iteration → Θ(n² log²n).
  • ✗
    T(n) = T(n/3) + T(2n/3) + n — Two different subproblem sizes. Use Recursion Tree → Θ(n log n).
  • ✗
    T(n) = T(n-1) + 1 — Subproblem decreases by subtraction, not division. Master Theorem needs division.

Impact: Why This Matters

Knowing time complexity lets you:

Compare algorithms: Merge Sort O(n log n) is always better than Bubble Sort O(n²) for large n.
Design better algorithms: Strassen reduces 8 multiplications to 7 → from O(n³) to O(n^2.807).
Predict if your code will finish in time before you even run it.

Key Warnings

⚠
n log n is NOT polynomially greater than n. The Master Theorem requires polynomial difference (at least n^ε for some ε > 0).
⚠
T(n) = A(n-1)+n means A calls itself with (n-1) and then does +n after. The recurrence is T(n)=T(n-1)+1 — the return value complexity, not the value itself.
⚠
Master Theorem needs b > 1 (subproblem must be strictly smaller). T(n) = 2T(n) + 1 is invalid.
