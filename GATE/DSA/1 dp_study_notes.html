How everything connects

The entire story of DP: notice that plain recursion repeats work exponentially → add memoization (same code, just cache results) → or flip to tabulation (fill from base cases up). Both achieve O(n). The magic: total recursive calls = O(2ⁿ) but unique sub-problems = only O(n).

Section 1

Why plain recursion is painfully slow

Take fib(n). Each call spawns 2 more calls. The tree doubles at every level. For n=40, this means over a billion function calls.

int Fibonacci(int n) {
  if (n == 0 || n == 1) return 1;
  return Fibonacci(n-1) + Fibonacci(n-2);
}
// T(n) = T(n-1) + T(n-2) + 1  ≈  O(2ⁿ)
// fib(40) → ~2 billion calls
Time: O(2ⁿ)Space: O(n) call stack

Interactive recursion tree — spot the repeated work

Key Observation (slide 9)

Total calls = O(2ⁿ). Unique calls = only O(n). The ratio between these is the waste DP eliminates. For fib(7): fib(5) computed twice, fib(4) three times, fib(3) five times.

Section 2 — Top-Down

Memoization — "Check before computing"

Add a single check (the guard) at the top of the recursive function. Before doing any work, ask: "Did I already compute this?" If yes, return the stored answer instantly.

// dp[] initialized to -1 ("not yet computed")

int Fibonacci(int n) {
  // GUARD — hit this on any repeated call
  if (dp[n] != -1) return dp[n];

  if (n == 0 || n == 1) { dp[n] = 1; }
  else {
    dp[n] = Fibonacci(n-1) + Fibonacci(n-2); // store then return
  }
  return dp[n];
}
Time: O(n)Space: O(n)
✦ The magic moment

When fib(5) is called for the 2nd time, instead of spawning an entire subtree of ~8 more calls, the guard fires and returns the answer in O(1). This single check collapses O(2ⁿ) total calls to O(n) unique calls.

  • Same structure as naive recursion — you don't change how you think. Just add caching.
  • Guard at top: if (dp[n] != -1) return dp[n] — this is the entire DP change.
  • Store before return: dp[n] = result; return dp[n];
  • Each unique sub-problem solved exactly once — subsequent calls are O(1).
Top-down fills the table lazily

The table is only filled for sub-problems that are actually needed. For recurrences like fun(i/2, j/2), only O(log²n) cells out of n² are needed — top-down is much faster here than bottom-up which fills all n² cells.

Section 3 — Bottom-Up

Tabulation — "Build from base cases upward"

No recursion at all. Start with the smallest known answers (base cases) and fill the table iteratively until you reach the answer you want.

int Fibonacci(int n) {
  dp[0] = dp[1] = 1;          // base cases

  for (int i = 2; i <= n; i++)
    dp[i] = dp[i-1] + dp[i-2]; // use already-filled values

  return dp[n];
}
Time: O(n)Space: O(n)No recursion overhead

Section 4 — Worked Examples

Building DP instinct through examples

Example 1: Climbing Stairs (count ways)

Problem: n-step staircase. Each move: climb 1 or 2 steps. Count distinct ways to reach the top.

Samples: n=2 → 2 ways. n=3 → 3 ways (1+1+1, 1+2, 2+1).

DP derivation

  • Define subproblem: cs[n] = number of distinct ways to climb n steps.
  • Find recurrence: To reach step n, I came from n-1 (1 step) or n-2 (2 steps). So cs[n] = cs[n-1] + cs[n-2]. This is exactly Fibonacci!
  • Base cases: cs[0]=1 (one way to stand at bottom), cs[1]=1.
  • Fill table: left to right, 0 to n.

Example 2: Row of Coins (max non-adjacent sum)

Problem: Row of coins c₁…cₙ. Pick coins for max total value. Constraint: cannot pick two adjacent coins.

Example: [5,1,2,10,6,2] → pick c₁=5, c₄=10, c₆=2 → total=17.

Key decision at each coin

  • Take coin n: gain cₙ, but cannot take n-1. Best = cₙ + f(n-2).
  • Skip coin n: Best = f(n-1).
  • Recurrence: f(n) = max(cₙ + f(n-2), f(n-1)). Base: f(0)=0, f(1)=c₁.

Example 3: Min Cost Climbing Stairs

Problem: cost[i] = cost of stepping on stair i. Pay cost, then move 1 or 2 steps. Start from 0 or 1. Find min total cost to reach past the last stair.

n=3: cost=[10,15,20] → 15 (start at index 1, pay 15, jump 2 steps to top).

Tricky: cost=[1,100,1,1,1,100,1,1,100,1] → 6 (jump over all 100s).

Define answer[n] = min cost to reach step n (not stand on it)

  • answer[0] = 0 (free to start here).
  • answer[1] = cost[0] (reach step 1 by paying cost[0] and jumping 1).
  • answer[n] = min(answer[n-1]+cost[n-1], answer[n-2]+cost[n-2]).
  • Final answer = answer[len(cost)] — one step past the array.

Example 4: Ants vs Bees — 2D DP + Probability

Problem: Ants and Bees play games. Ants win each game with prob p, Bees with q=1-p. First to n wins takes the series. Let P(i,j) = prob Ants win when Ants need i more wins, Bees need j more wins.

  • Next game: Ants win (prob p) → state (i-1, j). Bees win (prob q) → state (i, j-1).
  • Total probability: P(i,j) = p·P(i-1,j) + q·P(i,j-1).
  • Base cases: P(0,j)=1 (Ants done). P(i,0)=0 (Bees done).
  • 2D table: Fill row-by-row — P(i,j) depends on (i-1,j) and (i,j-1), both already filled.
// Top-down with 2D dp table
double fun(int i, int j) {
  if (dp[i][j] != NULL) return dp[i][j];  // guard
  if (i == 0) return dp[i][j] = 1;         // Ants won
  if (j == 0) return dp[i][j] = 0;         // Bees won
  dp[i][j] = p * fun(i-1,j) + (1-p) * fun(i,j-1);
  return dp[i][j];
}

Section 5

Bottom-Up Fill Order — the tricky part

In bottom-up DP you must fill cells in an order where every dependency is already computed. This is automatic in top-down but requires careful thought in bottom-up.

RecurrenceFill OrderPossible?
A(i,j-1), A(i-1,j-1), A(i-1,j+1)Row by row (i=0→n, j=0→n)✓ Yes
A(min{i,j}-1,…) and A(max{i,j}-1,…)Fill diagonal A(k,k) first, then any order✓ Yes
A(i-2,j-2) and A(i+2,j+2)—✗ Cyclic — impossible
⚠ Cyclic = no valid fill order exists

If dp(i,j) needs dp(i+2,j+2) which itself might need dp(i,j) again → infinite loop. Even top-down fails here as the recursion loops. This is a broken recurrence, not a DP problem at all.

When top-down may be faster than bottom-up

Slide 50-51: Special case

Consider fun(i,j) = max(fun(i/2,j), fun(i,j/2)) starting from (n,n). This keeps halving — only O(log n × log n) cells get touched. Bottom-up fills the full n×n table. Top-down only fills the needed cells → space O(log²n) vs O(n²). Big win!

Section 6

The 5 Elements of Dynamic Programming

① Optimal Substructure

What: Optimal solution to big problem is built from optimal solutions to smaller sub-problems of the same kind.

Test: Can you write a recurrence? Does the big answer depend on smaller answers?

② Overlapping Subproblems

What: The same subproblem is solved more than once in the recursion tree.

Why it matters: This is what makes DP worthwhile. Merge sort has NO overlapping subproblems — memoization gives zero benefit there.

③ Recurrence Relation

How to find it: Think about the last decision or last step. What choices were made? What follows each choice?

Example — coins: At coin n, either take it (cₙ + f(n-2)) or skip it (f(n-1)). Recurrence = max of both.

④ Base Cases

Smallest sub-problems with directly known answers. Without them, recursion never terminates. Common: dp[0], dp[1], P(0,j)=1, P(i,0)=0.

⑤ DP Table

Array (1D or 2D) to store computed results. One entry per unique subproblem. 1D for single-parameter problems, 2D for two-parameter problems like Ants/Bees.

✦ Recipe to solve any DP problem
  1. Define subproblem clearly in words — what does dp[i] mean?
  2. Write recurrence — think about last decision
  3. Write base cases — smallest known answers
  4. Choose approach — top-down or bottom-up
  5. If bottom-up: determine fill order
  6. Return dp[target]
Section 7

DP vs Divide and Conquer

Both break a big problem into smaller sub-problems. The crucial difference: do sub-problems overlap?

AspectDivide and ConquerDynamic Programming
Sub-problems overlap?No (independent)Yes (same ones repeat)
Use memoization?No benefitEssential
Classic examplesMerge sort, Binary searchFibonacci, Shortest path, Knapsack
Naive time complexityAlready optimalExponential (DP fixes it)
Intuition (slide 58-59)

Merge sort: mergeSort(1..n/2) and mergeSort(n/2+1..n) work on completely different data — no overlap. Fibonacci: fib(n-1) and fib(n-2) both internally call fib(n-2) — overlap! DP saves time only because of this overlap.

Why is it called "Dynamic" Programming?

Named by Richard Bellman in the early 1950s at Rand Corporation. The US Secretary of Defense Charles Wilson was "against research, especially mathematical research." Bellman chose "dynamic" because no one could oppose such a positive-sounding word.

"I used it as an umbrella for my activities." — Richard E. Bellman

⚡ Quick Revision — Dynamic Programming

What is DP?

  • DP = Careful Recursion = Careful Brute Force
  • Break problem into overlapping sub-problems, solve each once, store results
  • Two conditions: Optimal Substructure + Overlapping Subproblems
  • Named by Richard Bellman (1950s) — word "dynamic" was chosen to confuse anti-math officials

Why plain recursion fails

  • fib(n) naive → O(2ⁿ) total calls (exponential)
  • Only O(n) unique calls exist — everything else is repeated waste
  • Key insight: total calls ≫ unique calls → DP exploits this gap

Memoization (Top-Down)

  • Add guard: if dp[n] ≠ -1 → return dp[n]
  • After computing: dp[n] = result, then return dp[n]
  • O(n) time, O(n) space
  • Fills table lazily — only needed cells
  • Automatic fill order (recursion handles it)
  • Preferred when writing algorithms

Tabulation (Bottom-Up)

  • Start from base cases, fill iteratively forward
  • No recursion, no stack overflow risk
  • Must explicitly decide correct fill order
  • O(n) time, O(n) space
  • Preferred for solving exam questions

Key recurrences

  • Fibonacci: fib[i] = fib[i-1] + fib[i-2]
  • Climb stairs: cs[n] = cs[n-1] + cs[n-2] (same as fib!)
  • Row of coins (max non-adj): f[n] = max(cₙ + f[n-2], f[n-1])
  • Min cost stairs: ans[n] = min(ans[n-1]+cost[n-1], ans[n-2]+cost[n-2])
  • Ants vs Bees: P(i,j) = p·P(i-1,j) + (1-p)·P(i,j-1); P(0,j)=1; P(i,0)=0

Fill order for 2D DP

  • Check what dp[i][j] depends on — all must be filled first
  • Row-wise works when deps are at (i-1,*) or (i,j-1)
  • Cyclic dependency → no valid order → bottom-up impossible
  • Top-down saves time when only O(log²n) of n² cells are ever needed

DP vs Divide and Conquer

  • D&C: disjoint sub-problems (merge sort — different halves)
  • DP: overlapping sub-problems (fib — fib(n-2) called from both branches)
  • Memoization only helps when sub-problems overlap

5 Elements of DP

  • ① Optimal substructure — can write recurrence
  • ② Overlapping subproblems — same call appears multiple times
  • ③ Recurrence relation — dp[n] in terms of smaller dp values
  • ④ Base cases — smallest directly known answers
  • ⑤ DP table — store computed results

Complexity summary

  • Naive recursion: O(2ⁿ) time
  • Both DP approaches: O(n) time, O(n) space for 1D problems
  • 2D DP (Ants/Bees): O(n²) time, O(n²) space
