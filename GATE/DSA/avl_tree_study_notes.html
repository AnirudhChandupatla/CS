10,000 Feet View — What & Why AVL?

🔑 The Core Problem

A Binary Search Tree (BST) gives us O(log n) for search, insert, delete — only if the tree is balanced. But if you insert sorted data like 1, 2, 3, 4, 5… the BST becomes a linked list (height = n), making all operations O(n). That is terrible!

❌ BST — Worst Case

Looks like a linked list. Search is O(n). Useless!

✅ AVL Tree — Guaranteed

Height is always O(log n). All operations fast!

How All Concepts Connect Together

Every concept builds on the previous one. Master each step and the whole picture becomes clear.

The Journey of Suggestions Before AVL

Before AVL, people tried simpler balance conditions. All failed (or were too strict):

#SuggestionIdeaProblemVerdict
S1 Equal nodes at root Left & right subtree of root have same #nodes Subtrees can still be internally skewed (7 nodes on left, all in a line!) FAIL
S2 Equal nodes + height at root Same #nodes AND same height at root Still not recursive — deep subtrees can be skewed FAIL
S3 Equal nodes at every node For every node, left and right have same #nodes Height IS always log n, but you can only make perfect trees! Can't add/remove freely. TOO STRICT
AVL Balance factor ∈ {-1,0,+1} For every node: |height(left) - height(right)| ≤ 1 None — works for all shapes, ensures O(log n) ✅ PERFECT
✨ Key Insight

AVL found the sweet spot: not too strict (like S3 which forces perfect trees) and not too loose (like S1/S2 which allow skew). The balance factor trick is the magic!

AVL Tree — Definition & Balance Factor

Official Definition

An AVL tree is a Binary Search Tree where for every node:

Balance Factor (BF) = Height(Left Subtree) − Height(Right Subtree)
BF must be ∈ { −1, 0, +1 } for ALL nodes
If any node has |BF| > 1 → NOT an AVL tree → needs rebalancing

Height Convention

⚠️ Height of a null (empty) subtree = −1 (some books use 0 for leaf, −1 for null)

Height of a single leaf node = 0

Height of a node = 1 + max(height of left child, height of right child)

Node Structure

The AVL tree node has one extra field compared to a normal BST node — the height:

// BST Node
struct BSTNode {
  int data;
  BSTNode* left;
  BSTNode* right;
};

// AVL Node — just one extra field!
struct AVLNode {
  int data;
  AVLNode* left;
  AVLNode* right;
  int height;   // ← this is the key addition!
};

Examples: Is it an AVL Tree?

Example 2 NOT an AVL tree — find the bad node

Node 10 has left height = 3, right height = -1 (null), so BF = 3 − (−1) = 4 ❌

Node 7 has BF = 2 ❌. Both violate the AVL property.

⚠️ Common Mistake

Always check every single node, not just the root! A tree can look balanced at the root but have an internal node with BF = ±2.

Rotations — The Balancing Mechanism

✨ The Ingenious Idea — "Stick to Mountain"

When a subtree is unbalanced, it forms either a Stick (straight line) or an Elbow (bent). The fix is always: convert to a Mountain (balanced subtree).

The lecture introduces this as the "LO-STIC method" — much more intuitive than memorizing LL/RR/LR/RL names!

The Two Shapes That Cause Imbalance

🪄 STICK (Single Rotation)

All 3 nodes in one direction. Middle node (Y) becomes root = single rotation.

🪄 ELBOW (Double Rotation)

Nodes go left-then-right (or vice versa) = elbow shape. Z (middle by value) becomes root.

The 4 Rotation Types

NameShapePath from imbalanced nodeFix
LL Rotation Left-Left Stick Go left, then left Single right rotation (stick → mountain)
RR Rotation Right-Right Stick Go right, then right Single left rotation (stick → mountain)
LR Rotation Left-Right Elbow Go left, then right RR on left child, then LL on root (elbow → mountain)
RL Rotation Right-Left Elbow Go right, then left LL on right child, then RR on root (elbow → mountain)

General Rotation with Subtrees A, B, C, D

In real trees, each X/Y/Z node has subtrees attached. Here's how they move:

LL / Right Rotation — Before and After with subtrees
How to remember subtree placement

In-order traversal must stay sorted. So the sorted order is always: A < X < B < Y < C < Z < D. After rotation, just place each subtree where BST property requires it.

Rotation Code (LL Rotation)

// LL Rotation — right rotation around X
AVLNode* LL_Rotation(AVLNode* X) {
    AVLNode* t = X->left;        // t = Y
    X->left = t->right;          // X's left = C (Y's right subtree)
    t->right = X;                // Y's right = X

    // Update heights (IMPORTANT!)
    X->height = max(height(X->left), height(X->right)) + 1;
    t->height = max(height(t->left), height(t->right)) + 1;

    return t;  // Y is new root
}

// LR Rotation — double rotation
AVLNode* LR_Rotation(AVLNode* X) {
    X->left = RR_Rotation(X->left);  // First: RR on left child
    return LL_Rotation(X);            // Then: LL on X
}
⚠️ Critical: Update Heights!

After every rotation, you must update the height of X first, then Y (bottom-up). Forgetting this will break the entire tree.

AVL Insertion

Algorithm Overview

AVL Insert = BST Insert + Balancing

After inserting, check balance factors starting from the inserted node, going up to root. Find the first imbalanced node. Determine if it's a Stick or Elbow. Rotate once. Done!

✨ Magic Fact for Insertion

In insertion, you only ever need at most ONE rotation (either stick or elbow). After fixing the first imbalanced node, all ancestors automatically become balanced. This is why insertion is O(1) extra work beyond BST insert!

Step-by-Step Algorithm

  • 1
    BST Insert — insert the new node exactly like a normal BST (compare and go left/right until null)
    This places the node in the correct position to maintain BST property
  • 2
    Walk up from inserted node to root — check balance factor at each ancestor
    Only ancestors can be affected by the new node
  • 3
    Find first imbalanced node (BF = ±2) — call it Z
    This is the lowest unbalanced ancestor
  • 4
    Identify shape: Go from Z toward inserted node. Is it a stick (LL/RR) or elbow (LR/RL)?
    The shape determines which rotation to apply
  • 5
    Rotate — convert stick/elbow to mountain. Update heights.
    One rotation fixes everything for insertion

Worked Examples

Basic Insert 3, 2, 1 — LL Rotation

What happened: Inserted 1 → walked up: 2 balanced (BF=1→now 1), 3 is first imbalanced (BF=2). Path from 3 to 1 = 3→2→1 = Left-Left = STICK. Y=2 comes to top. Result: 2 is root, 1 and 3 are children.

Medium Insert 30, 10, 20 — LR (Elbow) Rotation

What happened: Path from Z(30) to new node 20: 30 → 10 → 20 = Left then Right = LR Elbow. Z=Y in elbow notation = 20 goes to top. Result: 20 is root, 10 left, 30 right.

Hard (University Level) Insert 9, 27, 50, 15, 2, 21, 36 — Multiple Rotations (UCSD exam question)

Follow each insertion carefully, checking balance after each:

  1. Insert 9 → single node, BF=0 ✓
  2. Insert 27 → 27 right of 9, BF of 9 = -1 ✓
  3. Insert 50 → 50 right of 27 → 9 has BF=-2 (RR Stick!) → RR rotation → 27 becomes root, 9 left, 50 right ✓
  4. Insert 15 → 15 goes left of 27, right of 9. All BFs okay ✓
  5. Insert 2 → 2 goes left of 9, left of 15. All BFs okay ✓
  6. Insert 21 → 21 goes right of 15 → 27 has BF=2 (LR Elbow!). Path: 27→9→15→21, key 3 nodes: Z=27, X=9, Y=15. LR rotation → 15 becomes root of this subtree, 9 left, 27 right
  7. Insert 36 → goes between 27 and 50. Check all BFs → balanced ✓

AVL Deletion

Algorithm Overview

AVL Delete = BST Delete + Balancing

Key difference from insertion: after deletion, you may need to rotate multiple times all the way up to root. Up to O(log n) rotations!

The Critical Challenge in Deletion — How to Identify Stick vs. Elbow?

✨ The Ingenious Rule for Deletion

In insertion, you know which direction the imbalance came from (the inserted node tells you). But in deletion, the imbalance direction isn't obvious — you deleted a node, so you can't "trace" to the inserted node.

Solution: From the imbalanced node Z, always go to the child with the HIGHER height. Then from that child, again go to the child with the higher height. This path defines stick or elbow.

Step-by-Step Algorithm

  • 1
    BST Delete — delete the node as in normal BST (replace with in-order successor/predecessor if internal node)
    Maintains BST ordering
  • 2
    Walk from deleted node up to root — check balance at each ancestor
    Any ancestor can become imbalanced
  • 3
    Find first imbalanced node Z (BF = ±2)
    Lowest unbalanced point
  • 4
    Identify shape: At Z, choose child with higher height (call it Y). At Y, choose child with higher height (call it X). If heights are equal at Y's children → always choose the stick direction (same side as Y relative to Z).
    Equal heights: elbow rotation would leave Y still imbalanced!
  • 5
    Rotate to fix Z. Update heights.
    Fixes local imbalance
  • 6
    Continue going up — do NOT stop! Check every ancestor until root.
    Unlike insertion, a fix here doesn't guarantee ancestors are balanced
⚠️ THE KEY RULE for equal heights

When you are at node Y and its two children have equal heights:

→ Always choose the stick path (same side as Y relative to Z)

→ NEVER choose elbow — it would result in Y being imbalanced after rotation!

WRONG Choosing elbow when heights are equal → Y becomes imbalanced after rotation → broken tree!

Insertion vs. Deletion — Key Difference

InsertionDeletion
Rotations needed At most 1 rotation Up to O(log n) rotations
How to find stick/elbow Trace path from imbalanced node to newly inserted node Follow the higher-height child at each step
After fixing one imbalance STOP — tree is balanced Keep going up to root
Equal-height tie-break N/A (path is clear) Always choose STICK

Worked Example

Medium Delete node 1 from this AVL tree
  • 1
    BST delete node 1. Node 2 becomes leaf.
  • 2
    Walk up: 2 is OK. 3 is imbalanced (BF = -2). This is Z.
  • 3
    At Z=3: left child=2 (h=0), right child=5 (h=2). 5 has higher height → Y=5
  • 4
    At Y=5: left=4 (h=0), right=6 (h=1). 6 has higher height → X=6
  • 5
    Path Z→Y→X is 3→5→6 = Right-Right = RR Stick. Rotate: 5 to top, 3 left, 6 right.
  • 6
    Check 5's parent (root). Root 5 is balanced. Done! (O(1) this time, but must always check to root)

    Maximum & Minimum Nodes — Height Analysis

    Question 1: Maximum Nodes in AVL Tree of Height h

    Intuition

    To maximize nodes for a given height h → fill every level as much as possible → use a perfect binary tree (all leaves at same level, every internal node has 2 children).

    N_max(h) = 2h+1 − 1
    Derived as: 2⁰ + 2¹ + 2² + ... + 2ʰ = 2^(h+1) − 1 (geometric series)
    Recurrence Form

    N(h) = N(h-1) + N(h-1) + 1 = 2·N(h-1) + 1

    Where: N(0) = 1 (single node), N(-1) = 0 (empty)

    Height hMax Nodes = 2^(h+1)−1Tree Shape
    01○ (single node)
    13○ with 2 children
    27Perfect tree, 3 levels
    315Perfect tree, 4 levels
    431Perfect tree, 5 levels
    563Perfect tree, 6 levels
    8511Perfect tree, 9 levels

    Question 2: Minimum Nodes in AVL Tree of Height h

    ✨ The Interesting One!

    To minimize nodes for a given height h → make the tree as sparse as possible while still maintaining AVL property. The AVL rule forces at least one subtree to have height h-1 (to keep the height = h). The other can be as small as h-2.

    N_min(h) = N_min(h-1) + N_min(h-2) + 1
    Base cases: N(0) = 1, N(1) = 2 — very similar to Fibonacci!

    Question 3: Minimum Height Given n Nodes

    Intuition — The "Brick" Analogy

    Think of nodes as bricks. If you want to minimize height, pack as many bricks per row as possible (perfect tree). Use the formula: find the smallest h such that 2^(h+1) - 1 ≥ n.

    Equivalently: h = ⌈log₂(n+1)⌉ − 1

    Exam Practice Find minimum height for n = 63 nodes

    From the table: N_max(5) = 63. So minimum height = 5.

    For n = 64 nodes: N_max(5) = 63 < 64, N_max(6) = 127 ≥ 64 → minimum height = 6.

    For n = 16 nodes: N_max(3) = 15 < 16, N_max(4) = 31 ≥ 16 → minimum height = 4.

    Height is Always O(log n) — The Proof Sketch

    Why height ≤ 1.44 log₂(n)?

    From the Fibonacci-like recurrence N_min(h) ≈ φʰ/√5 (where φ ≈ 1.618), we get:

    n ≥ N_min(h) → n ≥ φʰ/√5 → h ≤ 1.44 log₂(n)

    So AVL tree height is at most 1.44 × log₂(n) — barely more than perfectly balanced!

    Counting AVL Trees — Shapes & Structures

    Two Different Questions People Confuse

    Q1: How many distinct shapes of minimal AVL trees of height h exist? (structural shapes, no values)

    Q2: How many distinct AVL trees with keys 1..n and height h? (shapes × only 1 way to fill keys into each shape)

    The clever insight: given a shape (structure), there's only ONE way to fill BST keys (in-order traversal must match sorted order). So counting shapes = counting trees!

    NS(h) — Number of Distinct Minimal AVL Shapes of Height h

    A "minimal" AVL tree of height h is one with the minimum number of nodes (the Fibonacci AVL tree).

    The NS(h) Formula

    ✨ Key Insight — Product Rule!

    A minimal AVL tree of height h has one subtree of height h-1 and one of height h-2.

    For each shape of the h-1 subtree, there are NS(h-2) shapes for the h-2 subtree. So multiply! Also double for mirror images.

    NS(h) = 2 × NS(h-1) × NS(h-2)
    Base cases: NS(0) = 1, NS(1) = 2
    hNS(h)Note
    01Just one shape: single node
    12Left-heavy or right-heavy
    22 × 2 × 1 = 4LL, LR, RL, RR
    32 × 4 × 2 = 16Many combinations
    42 × 16 × 4 = 128Grows very fast!
    ⚠️ Why Product Rule (not sum)?

    For each of the NS(h-1) shapes on the left, ALL NS(h-2) shapes can appear on the right. So the total combinations = NS(h-1) × NS(h-2). Not plus — because it's independent choices on each side!

    Problem 2 — Medium (University of Washington) — AVL tree with {21,14,35,9,30,52,25,32,41,64}: Delete 14, then Delete 21
    ▶ Show Solution Outline

    First, build the tree by inserting all keys: 21,14,35,9,30,52,25,32,41,64. Multiple rotations happen during build.

    Delete 14: BST delete → 14's successor/predecessor replaces it. Walk up. Check if imbalance. At 21: left side lost a node. Right side heavier. Follow higher-height child. Apply rotation if needed.

    Delete 21: (now the modified tree's root if unchanged) → BST delete with successor. Check full path to root. May need up to O(log n) rotations.

    Key: After each deletion, remember to continue checking all the way up to root!

    Problem 3 — Hard (GATE-style) Min AVL tree height for exactly 100 nodes?
    ▶ Show Solution

    Use max nodes formula: N_max(h) = 2^(h+1) - 1. Find smallest h where this ≥ 100.

    • N_max(5) = 63 < 100
    • N_max(6) = 127 ≥ 100 ✓

    Minimum height = 6.

    Problem 4 — Tricky How many minimal AVL trees of height 4 exist?
    ▶ Show Solution

    Use NS(h) = 2 × NS(h-1) × NS(h-2)

    • NS(0) = 1
    • NS(1) = 2
    • NS(2) = 2 × 2 × 1 = 4
    • NS(3) = 2 × 4 × 2 = 16
    • NS(4) = 2 × 16 × 4 = 128
    Problem 5 — Very Tricky Is choosing elbow or stick always the same for insertion as deletion?
    ▶ Show Answer

    No, they are fundamentally different:

    • Insertion: You trace the path from the first imbalanced node down to the newly inserted node. The shape of this path (straight = stick, bent = elbow) determines the rotation.
    • Deletion: There is no "newly inserted node" to trace to. Instead, at each step, you follow the child with the HIGHER height. If heights are equal, you MUST choose stick (same direction as the child). Choosing elbow in equal-height case will leave the tree STILL imbalanced.

    This is the single most important conceptual difference!

    ⚡ Quick Revision — AVL Trees

    🔑 Core Definition

    AVL = BST + Balance Factor ∈ {-1, 0, +1} for EVERY node
    BF = H(left subtree) − H(right subtree)
    |BF| > 1 = imbalanced → needs rotation
    Extra field: Node stores its height (int)

    🔄 Rotations

    LL Stick → Single right rotation (Y to top)
    RR Stick → Single left rotation (Y to top)
    LR Elbow → RR on child, then LL on root (Z to top)
    RL Elbow → LL on child, then RR on root (Z to top)
    Stick: straight line (same direction)
    Elbow: bent (changes direction)
    Mountain: balanced result (Y/Z always at top)
    In-order: A < X < B < Y < C < Z < D

    ➕ Insertion

    Steps: BST insert → find first imbalanced → rotate
    Rotations: At most 1 (stick or elbow)
    Identify shape: trace path from Z to inserted node
    Time: O(log n)

    ➖ Deletion

    Steps: BST delete → walk up → fix each imbalance
    Rotations: Up to O(log n) — keep going to root!
    Identify shape: follow HIGHER-height child
    Equal heights: ALWAYS choose stick (elbow is WRONG)

    📊 Node Counts

    Max nodes (h): 2^(h+1) − 1
    Min nodes: N(h) = N(h-1) + N(h-2) + 1, N(0)=1, N(1)=2
    Min height (n nodes): smallest h where 2^(h+1)-1 ≥ n
    Height bound: always ≤ 1.44 × log₂(n)

    🔢 Counting Shapes NS(h)

    Formula: NS(h) = 2 × NS(h-1) × NS(h-2)
    NS(0)=1, NS(1)=2, NS(2)=4, NS(3)=16, NS(4)=128
    Product rule: independent choices on each side
    ×2 for: mirror images (left-heavy ↔ right-heavy)

    ⏱ Complexity

    Search: O(log n)
    Insert: O(log n)
    Delete: O(log n)
    Height: always O(log n) = guaranteed!

    🚨 Common Mistakes

    Using elbow when heights are equal in deletion
    Stopping after first fix in deletion
    Not updating height after rotation
    Using H(null) = 0 instead of −1
