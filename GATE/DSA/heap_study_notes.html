What is a Heap & Why Does It Exist?

The core problem: We often need to repeatedly find and remove the minimum (or maximum) element from a changing collection — e.g., job scheduling, Dijkstra's algorithm, priority-based systems. A sorted array is too slow to update; an unsorted array is too slow to search. We need something in between.

The ingenious idea: We don't need full sorted order. We only care about: "give me the min right now." A Heap gives us exactly that — partial ordering just good enough to always know the min in O(1), and to fix itself after each operation in O(log n).

Foundation

Heap Basics — Two Properties You Must Know

A heap is a Complete Binary Tree (CBT) that satisfies the heap property. Both must hold simultaneously.

🏗 Property 1: Structure

Complete Binary Tree:

  • All levels are completely filled except possibly the last
  • The last level is filled from left to right
  • This gives height = ⌊log₂ n⌋ → operations are O(log n)
🔑 Property 2: Order

Heap Property:

  • Min-heap: Parent ≤ both children (smallest on top)
  • Max-heap: Parent ≥ both children (largest on top)
  • Note: no ordering between siblings or cousins!
Key insight: A heap is NOT a sorted structure. Siblings can be in any order. It's a partial order — just enough to guarantee the root is always min (or max).

Storage

Array Representation — Magic Without Pointers

The problem with linked nodes: A binary tree with pointers needs extra memory and pointer navigation. But since a heap is a complete binary tree, there are no gaps — we can store it in a simple array using index math!

The magic formulas (1-indexed array):
Parent(i) = ⌊i/2⌋  |  Left(i) = 2i  |  Right(i) = 2i+1

For 0-indexed: Parent(i) = ⌊(i-1)/2⌋  |  Left(i) = 2i+1  |  Right(i) = 2i+2

Element Location

Where Are Min and Max? — The Important Facts

Min Heap

Min element: ALWAYS at root → O(1)

Max element: ALWAYS at a leaf → must scan ⌈n/2⌉ leaves → O(n)

Max Heap

Max element: ALWAYS at root → O(1)

Min element: ALWAYS at a leaf → must scan ⌈n/2⌉ leaves → O(n)

Why is max at a leaf in min-heap? From root going downward, values are non-decreasing (each child ≥ its parent). The largest value must be somewhere where it has no children forcing it to be larger. That's a leaf. But we don't know which leaf — could be any of the ~n/2 leaves.
GATE 2020 question: Min-heap with 1023 elements. Minimum comparisons to find maximum?
Answer: Max is in the leaves. A 1023-node complete binary tree has exactly 512 leaves (nodes from index 512 to 1023). We must compare all 512 leaves. So: 511 comparisons (to find max among 512 leaves using a tournament).
Advanced Property

Kth Minimum in a Min-Heap

Question: Where can the kth smallest element live in a min-heap?

Key Theorem: The kth minimum element in a min-heap is always located somewhere between level 0 (root) and level k−1 (inclusive).

Why? — The Logic

In a min-heap, as you go from root down any path, values are non-decreasing. So the first k elements in sorted order (1st min, 2nd min, ..., kth min) must all appear in the first k-1 levels.

1Root (Level 0) is always the 1st minimum.
By definition — root is ≤ all other elements in a min-heap.
22nd min must be at level 0 or 1.
It must be smaller than all elements below it. Since all children of root could be candidates, 2nd min is among the root's children (level 1).
3kth min cannot be lower than level k-1.
If kth min were at level k, there would need to be at least k elements smaller than it above it — but there are at most 2⁰+2¹+...+2^(k-1) = 2^k - 1 nodes above level k, and we'd need exactly k of those to be smaller. This can happen, but the kth min itself could still be at level k-1 or higher.
Tricky fact from notes: When elements repeat, the definition of kth smallest uses: "kth smallest is the minimum n such that at least k elements are ≤ n." For array [1,2,3,4,...,100] stored as min-heap, A[k] = kth min. But for [1,1,1,1,1,...], 2nd min = 1 (still the same value).

GATE CSE 2003 — 7th Smallest

In a min-heap with n elements, the 7th smallest element can be found in time:
Answer: Θ(1) — The 7th smallest is within the first 7 levels (levels 0–6). A heap with n elements has at most 2⁷−1 = 127 nodes in the first 7 levels. This is a constant (doesn't depend on n). So scan these 127 nodes → Θ(1).
Operation

Insertion — Percolate Up (Bubble Up)

Goal: Add new element while maintaining both CBT structure AND heap property.

Strategy: First maintain structure (add at end = next CBT position), then restore heap property (bubble up until parent is smaller).

Algorithm

1Add new element at the next available position (end of array)
This preserves CBT structure. Array size increases by 1.
2Compare with parent, swap if new element is smaller (min-heap)
If A[i] < A[i/2], swap them. Move up (i = i/2).
3Repeat until at root or parent is smaller
At most log n swaps (height of tree).

Construction

Build Heap — Two Approaches

Given an arbitrary array, how do we turn it into a valid heap?

Method 1: Top-Down (Repeated Insertion)
  • Insert elements one by one into empty heap
  • Each insertion: O(log n) worst case
  • n insertions → O(n log n)
  • Spends most time on leaves (log n per leaf)
Method 2: Bottom-Up (Heapify) ⭐
  • All leaves are already valid heaps!
  • Start from last non-leaf (⌊n/2⌋), heapify downward
  • Spends 0 time on leaves
  • Total: O(n) — much better!

The Genius of Bottom-Up: Why O(n)?

Heapify at each node costs O(height of that node). In a complete binary tree:
  • ~n/2 nodes at height 0 (leaves) → cost 0 each → total: 0
  • ~n/4 nodes at height 1 → cost 1 each → total: n/4
  • ~n/8 nodes at height 2 → cost 2 each → total: n/4
  • ~n/16 at height 3 → total: 3n/16 ...
Grand total = n/2 × [1/2 + 2/2² + 3/2³ + ...] = n/2 × 2 = O(n)
The series 1/2 + 2/4 + 3/8 + ... = 2 (converges!)

Heapify Algorithm (Percolate Down)

★Precondition: Both left and right subtrees of i are already valid heaps
We just need to fix node i by pushing it down to its correct position.
1Find the smallest among: node i, left child, right child
2If smallest is not node i, swap with the smallest child
3Recurse on the subtree where we swapped
Repeat until no swap needed or we reach a leaf. Cost: O(log n) worst case.

FindMin and DeleteMin

FindMin — O(1)

Simply return A[1] (root). The minimum is always at the root in a min-heap. This is the whole point of the heap! Constant time, no work needed.

DeleteMin — O(log n)

We must remove the root but maintain both properties:

1Save the root value (this is the min we're returning)
min = A[1]
2Move last element to root: A[1] = A[n], n--
This maintains CBT structure (removes last position = keeps it complete). But now heap property at root is broken.
3Heapify(A, 1) — percolate the root element down
Since both subtrees were already valid heaps (we only changed root), heapify fixes it by pushing root element down to correct position.

Summary: DeleteMin = 1 swap to root + at most log n heapify swaps = O(log n). Notice: avg case is also O(log n) for deletion (different from insertion where avg is O(1)).
Algorithm

Heap Sort — O(n log n), In-Place

Heap sort elegantly combines the two heap operations:

1Build a Max-Heap from the input array — O(n)
Use bottom-up heapify. We use max-heap (not min) so we can sort in ascending order in-place.
2Repeatedly delete max: swap root with last, heapify root — O(n log n)
Each deletion: A[1] ↔ A[n], shrink heap, heapify(1). This places largest at end, 2nd largest at n-1, etc.
Why max-heap for ascending sort? When we delete max and put it at the end of the array, the sorted portion grows from right. The deleted elements (in sorted order) live in the "used" portion of the same array — in-place, no extra space!

Counting

Number of Min-Heaps with n Distinct Elements

Given distinct values {1, 2, ..., n}, how many different valid min-heaps can be formed?

Key insight: The minimum (1) must always be at the root. Then we choose which elements go to the left subtree and which to the right. Recurse.

Formula

Let T(n) = number of min-heaps with n elements. The CBT shape is fixed for a given n (only one possible CBT shape). Let L = size of left subtree, R = size of right subtree.

  • Root is always the minimum (1 choice)
  • Choose L elements from remaining n-1 for left subtree: C(n-1, L)
  • Remaining R elements go right
  • Recursively arrange left: T(L), right: T(R)
T(n) = C(n-1, L) × T(L) × T(R)
Shortcut: T(n) = (n-1)! / (product of subtree sizes)

Shape: perfect BT with L=3 nodes, R=3 nodes.
T(7) = C(6,3) × T(3) × T(3) = 20 × 2 × 2 = 80

Probability a Random Permutation is a Min-Heap

P(random permutation = min-heap) = T(n) / n! = (n-1)! / (n! × product_correction) = 1 / product_of_sizes

For n=5 CBT shape: P = 1/(5×3) = 1/15. This is equal to (1/root_size) × P(left subtree) × P(right subtree).

Quick method: For each node, probability that this node is minimum of its subtree = 1/(subtree size). Multiply for all nodes.
Application

Priority Queue — Heap is the Best Implementation

A Priority Queue (PQ) is an abstract data type that supports: insert, delete-min (or max), and sometimes decrease-key.

Real-world need: OS task scheduling (urgent tasks first), Dijkstra's shortest path (always expand lowest-cost node), Huffman encoding, merge k sorted lists.

DecreaseKey in Heap

  • Decrease a key (make value smaller): Bubble the node UP (percolate up)
  • Increase a key (make value larger): Push the node DOWN (heapify)
Why heap wins: Average O(1) insertion is a huge advantage. For algorithms that insert many elements and only occasionally extract min (like Dijkstra with lazy deletion), heap is ideal.
Comparison

Heap vs Balanced BST

Heap Advantages
  • FindMin/FindMax: O(1) vs BST O(log n)
  • Average insertion: O(1) vs BST O(log n)
  • Build from array: O(n) vs BST O(n log n)
  • Cache-friendly (array storage)
  • Simpler to implement
BST Advantages
  • Search any element: O(log n) vs Heap O(n)
  • In-order traversal gives sorted order
  • Predecessor/successor queries
  • Range queries
  • Can find kth element more efficiently
Proof: Heap → BST cannot be done in O(n).
Assume it can. Then: Build heap O(n) + Convert to BST O(n) + In-order traversal O(n) = O(n) total. But this would sort in O(n), contradicting the Ω(n log n) comparison sort lower bound. Contradiction! So heap→BST must take at least Ω(n log n).

Merge Two Heaps

Combine arrays (size n and m), then build heap: O(n+m). This is much better than merging two BSTs.

Special case: if both heaps are perfect binary trees of same height → can merge in O(log n).

kth min in min-heap is between levels 0 to k-1. GATE 2003: 7th min findable in O(1) (constant number of nodes in first 7 levels).
GATE 2020: 1023-node min-heap → find max needs 511 comparisons (512 leaves, compare all).
Heap→BST cannot be O(n) (would break Ω(n log n) sorting lower bound).
