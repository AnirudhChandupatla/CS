⬆ STACK
Section 01

Abstract Data Types (ADT)

Before talking about Stack, understand what an ADT is. An Abstract Data Type specifies what operations can be performed on a collection — but not how those operations are internally implemented.

ADT = what you can DO (interface) NOT how it works internally Example: Stack ADT → Operations: push, pop, peek, isEmpty, isFull → Does NOT say: use array or linked list Same ADT, different implementations: Stack ──→ Array-based implementation └──→ Linked List-based implementation
Key idea
The user of the ADT only cares about what operations exist and their behavior. The internal structure is hidden (encapsulation). This is the "hiding" in the slides — ADT hides the data structure from the user.

A Stack is an ADT. An Array is a concrete data structure. Stack says "push and pop from one end only." An array says "I have random access by index." You use an array (or linked list) to build the stack.

Section 02

What is a Stack? (LIFO)

A Stack is a collection where insertion and deletion happen at the same end — the top. The other end is always closed. This creates the Last In, First Out (LIFO) property.

Think of a stack of plates. You always add and remove from the top. The plate at the bottom was placed first, but it comes out last.

Push sequence: A, B, C, D After push A,B,C: After push D: After pop D: ┌───┐ ← top ┌───┐ ┌───┐ ← top │ C │ │ D │ ← top │ C │ ├───┤ ├───┤ ├───┤ │ B │ │ C │ │ B │ ├───┤ ├───┤ ├───┤ │ A │ │ B │ │ A │ └───┘ ├───┤ └───┘ │ A │ └───┘

✦ The LIFO magic
Whatever you pushed last is what you get back first. This single constraint — access only the top — is what makes stacks so powerful for problems involving order reversal, nested structures, and "undo" logic.
GATE / ISRO Question
Q: Numbers 5, 222, 4, 48 inserted into a stack. Which is removed first?
A: 48 — the last one pushed is always the first one popped (LIFO).
Section 03

Why Stack? Use Cases

↩️ Undo Mechanism

Every action you do is pushed onto a stack. When you press Ctrl+Z, the last action is popped and reversed. The stack naturally gives you the most recent action first.

🔄 Reverse a Word

Push all characters onto a stack, then pop them one by one. Since LIFO reverses the order, you get the word reversed. Example: ABCD pushed → pop gives D, C, B, A.

📞 Function Call Stack

When main() calls f1(), which calls f2(), the OS pushes each function's activation record onto a call stack. When f2 returns, its record is popped. This is literally "the stack" your program has.

main() └─ f1() pushed └─ f2() pushed ← top ↑ popped when done
🔣 Expression Evaluation

Compilers use stacks to evaluate expressions and convert between infix/postfix/prefix notations. See Section 14–16 for the full details.

() Balancing Parentheses

To check if brackets are balanced, push opening brackets and pop when a closing bracket is found. See Section 12 for the full algorithm.

🧭 DFS / Backtracking

Depth-First Search in graphs uses a stack (explicit or call stack via recursion) to track the path and backtrack when needed.

Section 04

Stack Permutations & Catalan Numbers

A stack permutation is any output sequence that can be produced by pushing the input sequence (in order) and popping at any point.

Input arrives in order: 1, 2, 3, 4, ... You push them one by one, and can pop at any time. The output is the sequence of popped values.

Rule for Validity

A permutation is invalid if there exist positions i < j < k such that the output has the pattern k appears before i, and i appears before j — i.e., the pattern "k ... i ... j" where k > j > i in output. Formally: output contains the subsequence pattern (k, i, j) with k > j > i.

Example — Input: 1, 2, 3, 4

Which of these is NOT a valid stack permutation?

  • 1, 2, 3, 4 — valid (push 1 pop, push 2 pop, push 3 pop, push 4 pop)
  • 1, 3, 2, 4 — valid (push 1 pop, push 2 push 3 pop, pop 2, push 4 pop)
  • 1, 4, 2, 3 — INVALID. After popping 4, the stack has 3, 2. You can only get 3 then 2 (or just 2), but output says 2 then 3 → impossible.
  • 2, 1, 4, 3 — valid (push 1, push 2, pop 2, pop 1, push 3, push 4, pop 4, pop 3)
✦ Quick validity check
For output permutation [a, b, c...]: once you pop a value X, everything currently on the stack must come out in DESCENDING order before you can push new elements. If the output requires an element to come out in the wrong order relative to what's on the stack, it's invalid.

How Many Valid Stack Permutations?

The number of valid stack permutations of n elements is the Catalan number:

1 ²ⁿ C_n = ─── × C where ²ⁿCₙ = (2n)! / (n! × n!) n+1 n For n=2: C₂ = (1/3) × ⁴C₂ = (1/3) × 6 = 2 (valid: (()), ()() — i.e., 2 bracket arrangements) For n=3: C₃ = (1/4) × ⁶C₃ = (1/4) × 20 = 5 For n=4: C₄ = 14 Each valid permutation ↔ one valid bracket arrangement ↔ one stack order
Connection to brackets
Each push-pop pair is like one bracket pair ( ). The number of valid orderings of n push-pop pairs = the number of valid bracket strings of length 2n = Catalan number Cₙ.
GATE Question — Input: 5, 7, 8, 4, 6 in that order
Which output is possible? Answer: 7, 8, 4, 6, 5 (option d).
Why not 6, 8, 4, 7, 5? After popping 8, 4, 6 — 7 is still on stack below 5. You can't get 7 before 5.
Section 05

Array-Based Stack Implementation

The Idea

Use an array and an integer top. top starts at -1 (empty stack). Each push increments top and writes to array[top]. Each pop reads array[top] and decrements top.

Logical view: Physical (array) view: top → │ 1 │ index: 0 1 2 3 4 │ 7 │ value:[2] [5] [7] [1] [ ] │ 5 │ ↑ ↑ │ 2 │ front top=3 └───┘
int array[capacity];  // N = max size
int top = -1;         // -1 means empty

// Is Empty?
bool isEmpty() { return (top == -1); }

// Is Full?
bool isFull() { return (top == N - 1); }

// Push
void push(int value) {
    if (isFull()) { printf("Stack is full\n"); return; }
    array[++top] = value;  // increment top first, then assign
}

// Pop
int pop() {
    if (isEmpty()) { printf("Stack is empty\n"); return -1; }
    int data = array[top];
    top--;
    return data;
}

// Peek (look without removing)
int peek() {
    if (isEmpty()) return -1;
    return array[top];  // no top-- here!
}
Time Complexity
Push, Pop, Peek, isEmpty, isFull — all are O(1). No loops, no searching. Just index arithmetic.

Limitation of Array-Based Stack

⚠ Fixed size
The maximum size must be defined before use (int array[capacity]) and cannot be changed. If you don't know how large the stack needs to be, you either waste memory (over-allocate) or crash (under-allocate). This is the key limitation. Linked list implementation solves this.
ISRO 2015 / GATE 1991 — Trace Practice
Ops: push(1), push(2), pop, push(1), push(2), pop, pop, pop, push(2), pop
Pops output: 2, 2, 1, 1, 2 (answer A in ISRO 2015)
Always simulate on paper: draw the stack state after each operation.
Section 06

Linked List-Based Stack Implementation

In LL implementation, each stack element is a linked list node. The front of the list = top of the stack.

Push = insert at front of list (O(1)). Pop = delete from front of list (O(1)).

Stack state: top = 15 (most recently pushed) head → [15|●] → [10|●] → [20|●] → [44|NULL] ↑ ↑ TOP (push/pop here) BOTTOM
// Push: insert new node at front
void push(struct node **head, int data) {
    struct node *p = malloc(sizeof(struct node));
    p->data = data;
    p->next = *head;    // new node points to old head
    *head   = p;        // head becomes new node → O(1)
}

// Pop: delete from front
int pop(struct node **head) {
    if (*head == NULL) { printf("Empty\n"); return -1; }
    struct node *temp = *head;
    int data = temp->data;
    *head = (*head)->next;
    free(temp);
    return data;        // O(1)
}
⚠ Why NOT push/pop at the END of the list?
Inserting at end of SLL = O(1) only if you have a tail pointer. But deletion at end = O(n) because you must find the second-to-last node. Since stack needs BOTH push and pop at O(1), we always use the FRONT of the list as the top of the stack.

Section 07

What is a Queue? (FIFO)

A Queue is a collection where insertion happens at one end (the rear/back) and deletion happens at the other end (the front). This creates the First In, First Out (FIFO) property — whoever joined first, leaves first.

Think of a line of people at a billing counter. New people join at the back. The person at the front is served next.

←── dequeue (front) enqueue (rear) ──→ front/head rear ↓ ↓ [ 4 ] → [ 15 ] → [ 7 ] → [ 40 ] ↑ ↑ served next newly added

Operations

OperationWhat it doesWhere
EnQueue(data)Insert element at the rearRear end
DeQueue()Remove and return element from frontFront end
isEmpty()Is the queue empty?—
isFull()Is the queue full? (array only)—
getSize()Number of elements currently in queue—

Use Cases

🌐 Networking

Packets waiting to be routed. First packet in, first to be forwarded.

📞 Call Centers

Callers wait in a queue. First caller is served first when an agent is free.

💻 Operating Systems

CPU scheduling: processes in a ready queue. Also print queues, I/O queues.

🔍 BFS (Graph traversal)

Breadth-First Search uses a queue to explore nodes level by level.

Quick Question
Characters D, C, B, A placed in queue in that order. Removed one at a time. Order of removal?
Answer: D, C, B, A — queue is FIFO, so first in (D) is first out.
Section 08

Naive Array Implementation & Its Problem

The simplest idea: use an array with two pointers — front and rear, both starting at -1.

Enqueue: increment rear, store at array[rear]. Dequeue: read array[front], increment front.

Start: f = r = -1 (empty) After enqueue 1,9,7,6,8: front=0 rear=4 ↓ ↓ [ 1 | 9 | 7 | 6 | 8 | | | ] 0 1 2 3 4 After dequeue twice (removed 1, 9): front=2 rear=4 ↓ ↓ [ | | 7 | 6 | 8 | | | ]
⚠ The Problem — "False Full"
After many enqueue+dequeue operations, rear reaches the end of the array. But the front has moved forward, leaving empty slots at the beginning. The condition rear == N-1 says "full", but there IS space at the front. Slots 0 and 1 are wasted forever. This is the critical flaw of the naive approach.
After many enqueue+dequeue: rear = N-1 but front = 3 [ | | | 8 | 9 | 11 | 15 ] ↑ ↑ front rear ← says FULL but 3 slots free at left! SOLUTION → Circular Array
Section 09

Circular Array Queue Implementation

Core Idea: Treat the array as a ring. When rear reaches the last slot, it wraps back to index 0 using (rear + 1) % N. This reuses freed front slots — solving the "false full" problem of a naive linear queue.

Indices in memory: 0 1 2 3 4 5 Visualise as a ring: ┌── 0 ──┐ 5 ───┤ ├─── 1 4 ───┤ ├─── 2 └── 3 ──┘ After filling 3,4,5 and dequeuing 0,1,2 → next enqueue goes back to 0 rear = (rear + 1) % N ← the wrap-around formula
Two Initialization Conventions — both appear in GATE
Both use the same wrap-around formula and the same full-check (r+1)%N == f. They differ in what r points to, the empty condition, and how many slots can actually hold data.

Convention 1 in Depth: f = r = −1

Both start at −1, a sentinel meaning "no valid index yet." This lets the queue use ALL N slots because the empty state (f == −1) cannot be confused with any real index.

Key invariant — r always points to the last inserted element
After any EnQueue, array[r] holds the most recently added value. After any DeQueue, array[f] is the oldest remaining value. When empty, both are −1 — no valid index at all.

EnQueue — Convention 1

EnQueue(data):
    if ((rear + 1) % N == front):     // FULL? next rear slot would hit front
        print("Queue full"); return

    if (front == -1):                  // very first EnQueue — set front once
        front = 0                      // front never changes again except in DeQueue

    rear = (rear + 1) % N          // advance rear FIRST (wraps around at N)
    array[rear] = data               // store at the new rear position
First EnQueue walkthrough (N=6)
State: f=−1, r=−1.  Call EnQueue(42).
Full? (−1+1)%6=0 ≠ −1. Not full.
First element? f=−1 → set f=0.
r = (−1+1)%6 = 0.  array[0] = 42.
Result: f=0, r=0. Both at same index → exactly one element. ✓

DeQueue — Convention 1

DeQueue():
    if (front == -1):                 // EMPTY — f==-1 alone is sufficient to check
        print("Queue empty"); return -1

    data = array[front]

    if (front == rear):               // was this the last element?
        front = rear = -1           // reset both to sentinel — empty again
    else:
        front = (front + 1) % N     // advance front with wrap-around

    return data
Empty check — why f == −1 alone is enough
Whenever the last element is removed, we always set both f and r to −1 together. So at any point, either both are −1 or neither is. Checking front == −1 is computationally sufficient — checking both front == −1 && rear == −1 is correct but redundant. One check is the efficient choice.
Full state with Convention 1 — N = 6, all 6 slots used
EnQueue(1,2,3,4,5,6): After EnQueue(1): f=0, r=0 → [1| | | | | ] f==r → 1 element After EnQueue(2): f=0, r=1 → [1|2| | | | ] After EnQueue(3): f=0, r=2 → [1|2|3| | | ] After EnQueue(4): f=0, r=3 → [1|2|3|4| | ] After EnQueue(5): f=0, r=4 → [1|2|3|4|5| ] After EnQueue(6): f=0, r=5 → [1|2|3|4|5|6] ← ALL 6 slots used! Full check: (r+1)%N = (5+1)%6 = 0 = f → FULL r=5 holds value 6 (last inserted). Zero slots wasted.

Convention 2 in Depth: f = r = 0

Both start at 0. Here r is the "write cursor" — it always points to the next free slot where the next EnQueue will write. That slot is always empty. This makes the empty and full logic simple, but costs one slot.

Why one slot must be wasted
If all N slots were filled, r would have advanced to equal f — the same state as "empty" (f == r). We cannot distinguish completely full from completely empty. So full is declared early: when N−1 slots are used, (r+1)%N == f. The slot at r is always left empty.

EnQueue — Convention 2

EnQueue(data):
    if ((rear + 1) % N == front):     // FULL? N-1 slots already used
        print("Queue full"); return

    array[rear] = data               // store at current rear FIRST
    rear = (rear + 1) % N           // then advance rear to the next free slot
    // No special first-element case — front=0 is already a valid index

DeQueue — Convention 2

DeQueue():
    if (front == rear):               // EMPTY — f==r, no sentinel needed
        print("Queue empty"); return -1

    data = array[front]
    front = (front + 1) % N         // advance front; no reset to 0 needed
    return data
    // When last element removed, front advances to equal rear → f==r → naturally empty
Full state with Convention 2 — N=6, only 5 elements fit
EnQueue(1,2,3,4,5) with f=r=0 init: Start: f=0, r=0 → [ | | | | | ] r points to slot 0 (next free) EnQueue(1): arr[0]=1, r=1 → [1| | | | | ] EnQueue(2): arr[1]=2, r=2 → [1|2| | | | ] EnQueue(3): arr[2]=3, r=3 → [1|2|3| | | ] EnQueue(4): arr[3]=4, r=4 → [1|2|3|4| | ] EnQueue(5): arr[4]=5, r=5 → [1|2|3|4|5| ] Full check: (5+1)%6 = 0 = f → FULL — only 5 elements stored Slot 5 is empty, held by r — the permanently wasted slot

getSize() for Both Conventions

// Convention 1 (f = r = −1)
int getSize() {
    if (front == -1) return 0;                       // empty
    if (rear >= front) return rear - front + 1;        // no wrap (also works for f==r → 1)
    return N - front + rear + 1;                       // wrapped: e.g. f=4,r=1,N=6 → 4
}

// Convention 2 (f = r = 0)
int getSize() {
    return (rear - front + N) % N;                     // works for all cases (empty gives 0)
}

Section 10

Queue: Linked List Implementation

Use a linked list with TWO pointers: front (= head) for dequeue, and rear (= tail) for enqueue. Both operations are O(1).

front(head) rear ↓ ↓ [4|●] → [15|●] → [7|●] → [40|NULL] ↑ ↑ DeQueue from here EnQueue here
// EnQueue: insert new node at rear — O(1)
void enQueue(struct node **front, struct node **rear, int data) {
    struct node *newNode = malloc(sizeof(struct node));
    newNode->data = data;
    newNode->next = NULL;
    if (*rear == NULL) {         // first element
        *front = *rear = newNode;
        return;
    }
    (*rear)->next = newNode;    // attach to end
    *rear = newNode;            // update rear
}

// DeQueue: delete from front — O(1)
int deQueue(struct node **front, struct node **rear) {
    if (*front == NULL) { printf("Empty\n"); return -1; }
    struct node *temp = *front;
    int data = temp->data;
    *front = (*front)->next;
    if (*front == NULL) *rear = NULL;  // queue now empty
    free(temp);
    return data;
}
Summary: LL Queue
EnQueue = insert at END of list → O(1) (with tail pointer).
DeQueue = delete from FRONT of list → O(1).
No "isFull" needed — grows dynamically. Never wastes space like circular array.

Queue using 2 Stacks / Stack using 2 Queues

Queue using 2 Stacks (S1 and S2)

We have two stacks. We want to simulate a queue (FIFO) using only stack operations (push/pop).

Key insight: A stack reverses order. Two reversals restore original order. So push everything into S1 (reversed), then transfer to S2 (reversed again = original order), then pop from S2 = first in, first out.

EnQueue(Q, data):
    push(S1, data)  // O(1) always

DeQueue(Q):
    if S2 is not empty:
        return pop(S2)    // O(1) if S2 already has elements
    else:
        Transfer all from S1 to S2  // this reverses order
        return pop(S2)    // now in correct FIFO order
Trace Example

EnQueue(1), EnQueue(2), EnQueue(3), DeQueue()

After 3 enqueues: S1 = [3,2,1] (top=3) S2 = [] DeQueue called, S2 empty → transfer S1→S2: pop 3 from S1, push to S2 pop 2 from S1, push to S2 → S2 = [1,2,3] (top=3) pop 1 from S1, push to S2 S1 = [] pop from S2 → returns 1 ✓ (first in, first out!)
Complexity
EnQueue: always O(1). DeQueue: O(n) in worst case (when S2 is empty and we must transfer). But amortized over m enqueues + n dequeues, total cost is O(m+n) — each element is moved at most once between stacks.

Stack using 2 Queues (Q1 and Q2)

We want to simulate a stack (LIFO) using only queue operations (enqueue/dequeue).

Key insight: To pop (get the last-pushed element), we must move all BUT the last element from Q1 to Q2, then dequeue the last one from Q1, then swap Q1 and Q2 references.

Push(S, data):
    // Insert into whichever queue is non-empty
    if Q1 is not empty:  EnQueue(Q1, data)
    else:               EnQueue(Q2, data)  // O(1)

Pop(S):
    if Q1 is not empty:
        Transfer n-1 elements from Q1 to Q2
        data = DeQueue(Q1)   // last element = top of stack
        swap Q1 and Q2
    else:
        Transfer n-1 elements from Q2 to Q1
        data = DeQueue(Q2)
        swap Q1 and Q2
    return data            // O(n) — must traverse all but last
Note
One queue is always empty. Push is O(1), Pop is O(n). This is less efficient than a real stack. It's a classic exam question — not something you'd use in production.

Section 13

Two Stacks in One Array

Problem: Implement 2 stacks sharing a single array of size N efficiently — without wasting space.

Naive idea: Divide array in half. Stack1 uses indices 0 to N/2-1, Stack2 uses N/2 to N-1. Problem: one stack may overflow while the other still has space.

✦ Clever Solution: Grow from Both Ends
Stack1 grows from index 0 → rightward (top1 starts at -1). Stack2 grows from index N-1 → leftward (top2 starts at N). They only collide when there is truly no space left.
Array of size N=9: Stack1 → │ a │ b │ c │ d │ │ │ z │ y │ x │ ← Stack2 0 1 2 3 6 7 8 ↑ ↑ top1 top2 Full only when: top1 + 1 == top2 (they meet in the middle)
// Push to Stack 1
void push1(int x) {
    if (top1 + 1 != top2) array[++top1] = x;  // O(1)
    else printf("Full\n");
}

// Push to Stack 2
void push2(int x) {
    if (top1 + 1 != top2) array[--top2] = x;  // O(1)
    else printf("Full\n");
}
// Pop operations are symmetric — decrement top1 or increment top2

Push/Pop for both stacks remain O(1). Total space used is always optimal — no wasted slots until one stack truly needs it.

✦ Why Postfix/Prefix? The magic advantage
Postfix and prefix never need parentheses — the order of operators already encodes precedence. Computers can evaluate postfix in a single left-to-right scan using a stack. No backtracking, no parenthesis parsing. This is why compilers convert to postfix first.

Section 15

Infix → Postfix Conversion

Method 1 — Manual (Pen & Paper)

1
Add parentheses based on precedence and associativity. Every operator gets its own pair of parentheses around it and its operands.
2
Move each operator to the position of its closing parenthesis.
3
Remove all parentheses. What remains is postfix.
Example: x + y * z
Step 1: x + y * z → (x + (y * z)) * has higher precedence Step 2: Move * after its operands: (x + (y z *)) Move + after its operands: (x (y z *) +) Step 3: Remove brackets → x y z * + ✓
Example: a + b * c - d / e * f
With proper bracketing: ((a + (b * c)) - ((d / e) * f)) Convert inner brackets first: a + (bc*) - ((de/) * f) a + bc* - (de/f*) (a bc* +) - de/f* a bc* + de/f* - Postfix: a b c * + d e / f * -

Method 2 — Stack Algorithm (for programs)

Scan the infix expression left to right, character by character:

1
Operand (a, b, x, number) → immediately write to output.
2
Opening bracket ( → push onto stack.
3
Closing bracket ) → pop and output operators until you pop the matching (. Discard both brackets.
4
Operator (+ - * / ^):
  • While stack top has equal or higher precedence: pop and output.
  • Exception: ^ (right-associative): only pop if top has strictly higher precedence.
  • Then push the new operator.
5
End of input → pop all remaining operators from stack and output them.

Section 16

Evaluating Postfix Using a Stack

Postfix can be evaluated in a single left-to-right scan with a stack. No parentheses, no precedence checking needed.

Algorithm

1
Operand → push onto stack.
2
Operator → pop TWO operands: op2 = pop(), then op1 = pop(). Compute result = op1 OP op2. Push result back onto stack.
3
End of input → the single value remaining in the stack is the answer.
⚠ Order matters — pop op2 first, then op1
The first pop gives op2 (the right operand). The second pop gives op1 (the left operand). For subtraction and division, order matters: op1 - op2, NOT op2 - op1.
Trace: 3 10 5 + *
Token Stack ───────────────────── 3 [3] 10 [3, 10] 5 [3, 10, 5] + pop 5, pop 10 → 10+5=15 → push 15 [3, 15] * pop 15, pop 3 → 3*15=45 → push 45 [45] Result = 45 Infix equivalent: 3 * (10 + 5)
Trace: 3 10 5 − *
3, 10, 5 pushed → stack: [3, 10, 5] − → op2=5, op1=10 → 10−5=5 → stack: [3, 5] * → op2=5, op1=3 → 3*5=15 → stack: [15] Result = 15

Step by step: 10+5=15, 60/6=10, 15*10=150, 150−8=142 (Answer C)

Section 18 — The Mental Game

🧠 Pro Thinking — How to Become an Expert

This section rewires how you think about Stack and Queue problems. Internalize these models and you will solve problems you have never seen before.

Mental Models

🔁 Model 1: "The Reversal Machine"

A Stack is a reversal machine. Whatever order you put things in, they come out in the opposite order. This is powerful for: reverse a string, undo operations, reverse a list, evaluate expressions. Whenever a problem involves reversing or "going back", think Stack.

🚶 Model 2: "The Fair Queue"

A Queue is a fairness enforcer. First to arrive, first to be served. Use a queue whenever order must be preserved — BFS traversal, processing tasks in arrival order, simulating any real-world line. If LIFO is the reversal machine, FIFO is the preservation machine.

🪄 Model 3: "Two Stacks Cancel Out"

Two stacks together can simulate a queue. Two queues together can simulate a stack. This is because one reversal = wrong order, two reversals = right order. If a question involves converting between these two structures, think about the double-reversal property.

⚖️ Model 4: "The Parenthesis Model"

Push = opening bracket. Pop = closing bracket. Any nested structure (balanced brackets, function calls, recursive algorithms) maps directly to push-pop pairs. If you count opens and closes at any point, that's the current stack depth. Max stack depth = max nesting level.

🔣 Model 5: "Postfix = Natural Computer Order"

Infix notation is human-friendly but hard to parse. Postfix is computer-friendly — you evaluate left to right, using a stack, without ever needing to look ahead or handle precedence. Every time you see a postfix evaluation problem, just mechanically follow: operand → push, operator → pop two, compute, push result. One rule, no exceptions.

Edge Cases to Always Check

Stack Edge Cases
  • ✓ Push on full stack (array) → overflow error
  • ✓ Pop on empty stack → underflow error
  • ✓ Peek on empty stack → undefined / error
  • ✓ After pop, does isEmpty() return correct result?
Queue Edge Cases
  • ✓ EnQueue when full (circular) → (rear+1)%N == front
  • ✓ DeQueue when empty → front == -1
  • ✓ Last element DeQueue → reset front = rear = -1
  • ✓ getSize() when f > r (wrapped around) → use N-f+r+1
  • ✓ f = r = -1 means empty; do NOT confuse with f = r ≠ -1 (one element)
Expression Edge Cases
  • ✓ Pop order in postfix eval: op2 = first pop, op1 = second pop
  • ✓ Right-associative ^ : do NOT pop equal-priority ^ from stack when converting infix
  • ✓ Unary minus: e.g., 7 * -5 + 3 — treat -5 as a single operand
  • ✓ Functions like sin, max: treat like operators with highest precedence
  • ✓ Commas in functions act as operators of lowest precedence

How to Approach Any Stack/Queue Problem

1
Identify the access pattern. Do you need LIFO (last is relevant)? → Stack. FIFO (first is relevant)? → Queue. Both ends? → Deque.
2
Draw the state. Draw what the stack/queue looks like after each operation. For trace questions, NEVER try to solve in your head — always simulate on paper.
3
Identify what's on the stack at each point. For expression problems, ask: "What operators are waiting to be applied?" That's your stack content at any moment.
4
For circular queue: always use modulo. Draw the indices as a clock. Trace front and rear around the circle.
5
For validity questions (stack permutation, balanced brackets): simulate the process. If at any point the stack state is impossible, the answer is invalid.

Key Insights That Separate Beginners from Experts

💡 Insight 1: The "delayed" operator insight

In the infix-to-postfix algorithm, the stack holds operators that are waiting — they can't be output yet because a higher-priority operation might come later. When a lower-priority operator arrives, all the waiting higher-priority operators can finally be output. The stack is a "waiting room" for operators.

💡 Insight 2: Circular queue "one slot waste" is a design choice

You lose one slot to keep full and empty states distinguishable. If you don't want to waste a slot, you can instead maintain a size counter. Full when size == N, empty when size == 0. This alternative avoids wasting the slot but adds an extra variable to maintain.

💡 Insight 3: Stack can simulate recursion

Any recursive algorithm can be converted to an iterative one using an explicit stack. The recursion call stack IS a stack. DFS, tree traversals, expression parsing — all can be done iteratively with an explicit stack. This is important for memory optimization and for understanding how recursive programs work internally.

💡 Insight 4: Catalan numbers count many things

Stack permutations, valid bracket strings, BST shapes from n keys, polygon triangulations — all counted by the same Catalan number formula. Recognizing this connection helps you immediately answer "how many valid X" questions without re-deriving the formula.

Final Advice
The most common mistake with stacks and queues is not tracing through examples carefully. Always simulate. Draw the data structure state after EACH operation. The algorithms are simple — the errors come from rushing. For exam questions, if you simulate correctly, you will always get the right answer.
