LCS Problem Statement

A common subsequence of X and Y = a sequence that is a subsequence of both X and Y.

The Longest Common Subsequence (LCS) = the common subsequence with maximum length.

Formal Task

Given X of length m and Y of length n, find the length of their LCS (and optionally reconstruct the actual subsequence string).

Approach 1 — Naive

Brute Force — Enumerate All Subsequences

Algorithm:

  1. Enumerate all possible subsequences of X — there are 2m of them.
  2. For each one, check if it is also a subsequence of Y.
  3. Keep track of the longest one found.

Why 2ᵐ subsequences?

For each character in X (|X| = m), you have exactly 2 choices: include it or skip it. With m independent binary choices → 2m possible subsequences.

m=10 → 1024, m=20 → 1M, m=50 → 1015 → takes thousands of years.

Why Brute Force Fails → Motivation for DP

We recompute the same LCS sub-problems over and over inside the recursion. DP fixes this by storing each answer once — turning 2m repeated calls into exactly m×n calls total.

The Key Insight

Recursive Insight — Two Cases

Instead of checking all subsequences, we ask a smarter question: "What does LCS(X[1..i], Y[1..j]) look like, based on whether the last characters match?"

Case 1 — Last chars MATCH: X[i] = Y[j]

The Magic Insight

If the last characters match, they will always appear in some optimal LCS. Why throw away a free match? So we claim 1 for this pair, and recurse on the remaining prefixes.

LCS(i, j) = 1 + LCS(i-1, j-1)    // X[i] == Y[j]

Example: X = ABDE, Y = ZBE — both end in E

LCS(ABDE, ZBE) = 1 + LCS(ABD, ZB) → the E is in the LCS for free

Case 2 — Last chars DON'T MATCH: X[i] ≠ Y[j]

Critical Rule — You CANNOT decrement both at once

When X[i] ≠ Y[j], you might think: "drop both last chars → LCS(i-1, j-1)". This is WRONG.

Counter-example: X = PBT, Y = YXB. Last chars T ≠ B. If we drop both, we get LCS(PB, YX) = 0. But the real LCS is "B" (length 1) — dropping both hid it!

The correct logic: the optimal LCS either doesn't use X[i], or doesn't use Y[j] (since they can't match each other). Try both, take the max.

LCS(i, j) = max(
    LCS(i-1, j),    // drop X[i]  — maybe X[i] not in LCS
    LCS(i, j-1)     // drop Y[j]  — maybe Y[j] not in LCS
)                  // X[i] != Y[j]
Example: X = ABDG, Y = ZBD (last: G ≠ D)

The Formula

Complete Recursive Equation

LCS[i,j] = length of LCS of X[1..i] and Y[1..j]

// Base cases — empty string has LCS = 0
LCS[0, j] = 0    for any j
LCS[i, 0] = 0    for any i

// Recursive cases
LCS[i, j] = 1 + LCS[i-1, j-1]               if X[i] == Y[j]  (Case 1)
LCS[i, j] = max( LCS[i-1, j], LCS[i, j-1] )   if X[i] != Y[j]  (Case 2)

// Final answer
return LCS[m, n]   // m = |X|, n = |Y|

Cell Dependency — Which cells does (i,j) need?

Cell (i,j) depends on exactly 3 neighbors (diagonal, above, left)

■ diagonal (i-1,j-1)
Used in Case 1 (X[i]=Y[j]): 1 + diagonal

■ above (i-1,j)
Used in Case 2: drop X's last char

■ left (i,j-1)
Used in Case 2: drop Y's last char

Fill order: Row by row, left to right. Every cell only needs cells already computed. ✓

Pure Recursive Code

int LCS(int i, int j) {
    if (i == 0 || j == 0)   return 0;
    if (x[i] == y[j])        return 1 + LCS(i-1, j-1);
    else return max(LCS(i, j-1), LCS(i-1, j));
}
Complexity Deep Dive

Total Calls vs Unique Calls

Total Recursive Calls — Exponential 😱

Case 2 makes 2 sub-calls per call. This forms a binary tree of depth m. Result: 2m total calls in the worst case.

Recursion Tree — LCS(4,3). Notice LCS(3,2) appears twice (orange circles)
2ᵐ total calls (exponential) Same sub-problems recomputed many times

Unique Calls — Only m×n! 🎉

The Key Observation That Enables DP

LCS(i,j) is fully defined by 2 parameters: i ∈ {0..m} and j ∈ {0..n}. So there are at most (m+1)×(n+1) unique sub-problems. Store each result once → each computed only once.

m×n unique sub-problems Each computed exactly once O(m·n) time and space

DP Implementation

Bottom-Up DP — Table Filling

Create a table C of size (m+1)×(n+1). All row-0 and col-0 cells = 0. Fill left-to-right, top-to-bottom. Answer at C[m,n].

function LCS_DP(X[1..m], Y[1..n]):
    C[i,0] = 0   for all i     // base: empty Y
    C[0,j] = 0   for all j     // base: empty X
    
    for i = 1 to m:
        for j = 1 to n:
            if X[i] == Y[j]:
                C[i,j] = C[i-1,j-1] + 1          // Case 1: match
            else:
                C[i,j] = max(C[i-1,j], C[i,j-1])  // Case 2: no match
    
    return C[m,n]
Time: O(m·n) Space: O(m·n) Answer at C[m,n]

Memoized (Top-Down) Code

// dp[i][j] = null means not yet computed
int LCS(int i, int j) {
    if (dp[i][j] != null) return dp[i][j];  // cache hit
    if (i==0 || j==0) { dp[i][j]=0; return 0; }
    if (x[i]==y[j])  dp[i][j] = 1 + LCS(i-1,j-1);
    else             dp[i][j] = max(LCS(i,j-1), LCS(i-1,j));
    return dp[i][j];
}

Reconstruction

Backtracking — Find the Actual LCS String

After filling the table, start at C[m,n] and trace back to C[0,0] using the same rules that filled each cell.

BACKTRACK(i, j):
    if i==0 or j==0:  return ""
    if X[i] == Y[j]:
        return BACKTRACK(i-1, j-1) + X[i]     // ↖ diagonal — include char
    else if C[i-1,j] >= C[i,j-1]:
        return BACKTRACK(i-1, j)               // ↑ up — came from dropping X[i]
    else:
        return BACKTRACK(i, j-1)               // ← left — came from dropping Y[j]
↖ diagonal: X[i]=Y[j], include this character
↑ up: X[i]≠Y[j], came from dropping X[i]
← left: X[i]≠Y[j], came from dropping Y[j]
Multiple LCS Explanation

When C[i-1,j] = C[i,j-1] in Case 2, both paths are equally valid. Following different tie-breaking choices at these cells gives different LCS strings of the same length. This is why the example above has 3 valid LCS strings.

Alternative: Start from First Instead of Last

The conventional approach compares last characters (decrement i,j). An equivalent formulation starts from first characters (increment i,j).

Match1 + LCS[i-1, j-1]1 + LCS[i+1, j+1]
No-matchmax(LCS[i-1,j], LCS[i,j-1])max(LCS[i+1,j], LCS[i,j+1])

Used in practice?Yes (conventional)Rarely
Why Prefer Starting from Last?

Convention and convenience. Table fills naturally top→bottom, left→right. The answer lands at the bottom-right corner C[m,n], which feels intuitive. Starting from first reverses the fill order and puts the answer at C[1,1]. Both are mathematically valid.

Real World

Applications of LCS

🧬

Bioinformatics

Compare DNA/RNA/protein sequences. Similarity between two DNA strands is measured via LCS length. Used in phylogenetics and evolutionary biology.

📄

unix diff / GitHub

The diff command compares file versions. Lines not in the LCS are the additions/deletions shown in diffs and GitHub pull-request reviews.

🔤

Edit Distance

LCS relates to edit distance: edit_dist = m + n − 2×LCS_length (for insert/delete only). Used in spell checkers and fuzzy string matching.

🔐

Plagiarism Detection

Long common subsequences between documents suggest shared source material — even after reordering or paraphrasing sentences.

GATE Questions — Fully Solved

GATE 2009

Question:

l(i,j) = 0,      if i=0 or j=0
       = expr1,  if i,j>0 and X[i-1] = Y[j-1]
       = expr2,  if i,j>0 and X[i-1] ≠ Y[j-1]

A. expr1 = l(i-1,j)+1
B. expr1 = l(i,j-1)
C. expr2 = max(l(i-1,j), l(i,j-1))  ← answer
D. expr2 = max(l(i-1,j-1), l(i,j))
Answer: C — Why?

The question uses 0-indexed arrays (X[i-1], Y[j-1]). When X[i-1]=Y[j-1] → expr1 = l(i-1,j-1)+1 (diagonal+1). When X[i-1]≠Y[j-1] → expr2 = max(l(i-1,j), l(i,j-1)). Only option C correctly states expr2.

GATE 2014

Question: A = "qpqrr", B = "pqprqrp". x = LCS length, y = number of distinct LCS strings. Find x + 10y.

Solution

Step 1: Fill the DP table (rows=B=pqprqrp, cols=A=qpqrr).

Step 2: LCS length = x = 4. Candidates: pqrr (found in both), qprr, etc.

Step 3: Trace all backtrack paths → y = 3 distinct LCS strings.

Answer: x + 10y = 4 + 30 = 34

Tricky Cases to Know

No Common Characters

X = "ABC", Y = "DEF" → LCS = "" (empty), length = 0. All cells stay 0. C[3,3] = 0.

One is Subseq of Other

X = "ACE", Y = "ABCDEF" → LCS = "ACE", length = 3. The entire shorter string IS the LCS.

Identical Strings

X = Y = "ABCD" → LCS = "ABCD", length = 4. The diagonal gets filled with 1,2,3,4.

LCS vs Substring!

"ABCDEF" vs "ACGE" — LCS = "ACE" (length 3). But longest common substring would be shorter since substring must be contiguous.

DP Properties

  1. Optimal Substructure: LCS(m,n) = composed of optimal LCS(m-1,n-1/m-1,n/m,n-1).
  2. Overlapping Subproblems: Same (i,j) pairs needed by many parent calls → DP stores them.
  3. Multiple LCS: Same length, different strings — both valid. When C[i-1,j]=C[i,j-1], tie.
  4. LCS + Edit Distance: edit_dist = m + n − 2×LCS (for insert/delete only ops).

Space Optimization (2-row trick)

Each cell (i,j) only needs row i-1 and row i. So we can keep just 2 rows at a time → O(min(m,n)) space. Limitation: can't backtrack to find the actual LCS string (only length). Hirschberg's algorithm solves this in O(m·n) time and O(min(m,n)) space.

⚡ Quick Revision — LCS

Definitions

  • Subsequence: Drop some symbols (keep order) from a sequence. 2ᵐ subsequences possible from string of length m.
  • Common Subsequence: Appears as a subsequence in both X and Y.
  • LCS: The longest common subsequence (may not be unique).

The Two Cases

Case 1: X[i]=Y[j] → LCS[i,j] = 1 + LCS[i-1, j-1]
Case 2: X[i]≠Y[j] → LCS[i,j] = max(LCS[i-1,j], LCS[i,j-1])
Base: LCS[0,j] = LCS[i,0] = 0
  • CANNOT decrement both in Case 2 — you'd skip a hidden match.
  • Cell (i,j) depends on: (i-1,j-1) diagonal, (i-1,j) above, (i,j-1) left.

Complexity

  • Brute force: O(n·2ᵐ) — unusable.
  • Total recursive calls (no memo): 2ᵐ — exponential.
  • Unique sub-problems: (m+1)×(n+1) ≈ m×n.
  • DP time & space: O(m·n) — polynomial, feasible.

Table Filling

  • Size: (m+1)×(n+1). Row 0, Col 0 = all 0s (base cases).
  • Fill row-wise left→right (or column-wise, both work).
  • Answer at C[m,n].

Backtracking

  • Start at C[m,n]. If X[i]=Y[j] → go ↖ diagonal, add char to LCS.
  • If C[i-1,j] ≥ C[i,j-1] → go ↑ up.
  • Else → go ← left.
  • Tie at Case 2 → multiple valid LCS strings of same length.

Magic Insights

  • If last chars match, they ALWAYS appear in optimal LCS — never wasteful to include.
  • When no match, at most ONE of X[i] or Y[j] can be in LCS (since they differ) → try dropping each, take max.
  • 2ᵐ calls shrink to m×n by noticing (i,j) fully identifies any sub-problem.

GATE Tips

  • 0-indexed: X[i-1]=Y[j-1] ↔ 1-indexed: X[i]=Y[j]. Same formula, just index shift.
  • LCS ≠ Longest Common Substring (substring = contiguous; subsequence = non-contiguous ok).
  • GATE 2009: Answer C. | GATE 2014: x=4, y=3, answer=34.
  • LCS length + Edit distance: edit_dist = m + n − 2×LCS (insert/delete only).

  • unix diff, GitHub PR diffs.
