Big Picture

10,000-Foot Overview

This lecture extends the DP toolbox. We already know LCS, Matrix Chain Multiplication, and 0/1 Knapsack. Now we learn three more DP problems, understand where DP, Greedy, and Divide & Conquer differ, and end with two famous graph problems.

How the topics connect

Max Subset Sum → very similar to 0/1 Knapsack (profit = weight, just one value). Teaches the "take or don't take" recursion pattern.

Subset Sum (decision) → variation of Max Subset Sum. Instead of maximizing, just ask: can we hit exactly target T? Same table, different answer type (True/False instead of integer).

Coin Change → similar to Subset Sum but items are unlimited (can pick same coin many times). Shows how "unbounded" vs "0/1" changes one line of the recurrence.

DP vs Greedy vs D&C → now that we know multiple techniques, we understand when each applies: D&C splits but doesn't reuse sub-answers; DP reuses overlapping sub-answers; Greedy makes one "best local choice" and never looks back.

Floyd-Warshall → DP applied to graphs. Earlier Dijkstra/Bellman-Ford solved single-source shortest path. Floyd-Warshall solves all-pairs shortest path in O(V³).

TSP → the "boss level" where no polynomial-time algorithm is known. Shows limits of DP and why some problems are fundamentally hard (NP-Hard).

Topic 1

Maximum Subset Sum (MSS)

What is the problem?

Input: A set of integers, e.g. {6, 8, 9, 11, 13, 16, 18, 24}, and an integer K (budget).

Output: Find a subset whose sum is as large as possible without exceeding K.

Example: K = 21 → best possible = 20 (take 9+11). Cannot get 21, so 20 is the answer.

💡 How is this different from 0/1 Knapsack?

In 0/1 Knapsack: each item has both a profit and a weight. You maximize profit within weight budget.
In MSS: each item has only one value. That same value is both "weight" and "profit". You maximize sum ≤ K. It's the same algorithm — just simpler.

Recurrence relation

Define mss(i, W) = maximum subset sum, not exceeding W, using items 1..i.

mss(i, W) = 0 if i=0 OR W=0 = mss(i−1, W) if w_i > W [can't take item i] = max{ mss(i−1, W), mss(i−1, W−w_i)+w_i } otherwise [take or skip]
Why add w_i after mss(i−1, W−w_i)? Because we took item i, its value (w_i) must be added to the subproblem's result.
✨ Key Insight — why NOT option (a) from the lecture?

Option (a) was: max{ mss(i−1,W), mss(i−1, W−w_i) } — this is WRONG because if you take item i, you must add w_i to the answer. Without it, you reduce W but forget to count what you picked. Option (b) mss(i−1, W−w_i) + w_i correctly says: "I committed to item i (+w_i), now solve remaining budget."

Step-by-step tree example

Items = {6, 8, 9}, K = 15. Let's trace mss(3, 15):

mss(3, 15)   ← consider item 9 (w_3=9 ≤ 15, so 2 choices)
├── TAKE 9:   mss(2, 6) + 9     ← remaining budget = 15-9=6
│   ├── TAKE 8? 8 > 6 → SKIP: mss(1, 6) = max{skip 6: mss(0,6)=0, take 6: mss(0,0)+6=6} = 6
│   └── mss(2, 6) = max{skip 8: mss(1,6)=6, take 8? 8>6 skip} = 6
│       → mss(2,6) + 9 = 6 + 9 = 15  ✓
│
└── SKIP 9:  mss(2, 15)
    ├── TAKE 8: mss(1, 7) + 8 = max{skip 6: 0, take 6: 6} + 8 = 14
    └── SKIP 8: mss(1, 15) = max{0, 6} = 6
    → mss(2,15) = max(14, 6) = 14

mss(3,15) = max(15, 14) = 15  ← answer: pick items 6 and 9

Topic 2

Subset Sum (Decision Problem)

What is the problem?

Input: List of positive integers a[1..n], and a target integer T.

Output: Return True if any subset sums to exactly T. Otherwise False.

Example: a = [12, 1, 3, 8, 20, 50], T=44 → True (12+1+3+8+20=44). T=42 → False.

💡 How is this different from MSS?

MSS returns an integer (the best sum ≤ K). Subset Sum returns True/False (can we hit exactly T?). The recursion is almost identical — but instead of max{...}, we use OR (∨). And we can't add w_i anymore because the unit of return is boolean, not a number.

Recurrence relation

ss(i, S) = True if S = 0 [empty subset always works] = False if i=0, S≠0 [no items left, target not met] = ss(i−1, S) if a_i > S [item too big, must skip] = ss(i−1, S−a_i) ∨ ss(i−1, S) if S ≥ a_i [take OR skip]
The OR (∨) here is the key difference from Knapsack/MSS which use max/min.
✨ Why OR, not max?

Both subproblems return True or False. We can't take max of True/False. Instead: if either choice leads to success, the answer is True. So it's logical OR: "Does taking a_i work OR does skipping a_i work?" If yes to either → True.

Working example with full DP table

Items = {10, 5, 15}, Target S = 20. Can we get exactly 20?

Items indexed 1=10, 2=5, 3=15. S from 0..20 (showing 0..5 and key values).

i\S012345...101520
i=0 (no items) TFFFFFF...FFF
i=1 (item:10) TFFFFFF...TFF
i=2 (item:5) TFFFFTF...TTF
i=3 (item:15) TFFFFTT...TTT ✓
How to read the table

Row i=0: No items. Only S=0 is True (empty subset).
Row i=1 (item=10): S=10 becomes True because we can take item 10. S=0 still True (skip everything).
Row i=2 (item=5): S=5 now True (take item 5). S=15 True (5+10). S=10 stays True.
Row i=3 (item=15): S=20 → check ss(2, 5) ∨ ss(2, 20). ss(2,5)=True → answer is True! ✓
Final answer: ss(3, 20) = True. We can make 20 with {5, 15}.

Three interesting cases

Easy: Target is sum of all elements → always True

Moderate: Target = 43 in {12,1,3,8,20,50} → True (12+1+3+8+20-1 = skip 1? Let's check: 12+3+8+20=43 ✓)

Tricky: Target = 42 in same list → False (no combination gives exactly 42)

Top-Down vs Bottom-Up advantage

Bottom-Up (fills entire table)

For {10,5,15} with S=20: fills ALL entries in a (3+1)×(20+1) = 84-cell table, even entries never needed for the answer.

Top-Down (fills only needed)

Only computes: ss(3,20), ss(2,5), ss(1,0)→T, ss(2,20), ss(1,15)→F, ss(1,20)→F. Just 7 entries! Much faster for sparse targets.

Topic 3

Coin Change Problem (Minimum Coins)

What is the problem?

Story: You are a shopkeeper needing to return Rs.31 to a customer. You have unlimited coins of denominations [25, 10, 5, 1]. What is the minimum number of coins to use?

Answer: 25+5+1 = 3 coins. (Not 25+1+1+1+1+1 = 6 coins!)

Key difference from 0/1 Knapsack: Coins are unlimited. You can use the same coin multiple times!

⚠️ Why greedy fails here

Coins = [25, 10, 20, 1], S = 30. Greedy picks 25 first (largest). Remaining = 5. But 5 can't be made with {10,20,1} without 5 coins of 1. Greedy gives 6 coins (25,1,1,1,1,1). Optimal is 2 coins (20+10)! Greedy can't "take back" the bad choice of 25.

Recurrence relation

Define CC(i, S) = minimum coins to make change S, using coin types 1..i (each unlimited).

CC(i, S) = 0 if n=0 OR S=0 [no change needed] = CC(i−1, S) if v_i > S [coin too big] = min{ 1 + CC(i, S−v_i), CC(i−1, S) } otherwise [take OR skip]
Why CC(i, S−v_i) and NOT CC(i−1, S−v_i)? Because coins are UNLIMITED — after taking coin i, we can take it AGAIN (keep i, not i−1).
✨ The Magic Difference: i vs i−1
0/1 Knapsack (one use per item)
After taking item i:
→ mss(i−1, W−w_i) + w_i
// Move to i-1, item used up
Coin Change (unlimited use)
After taking coin i:
→ 1 + CC(i, S−v_i)
// Stay at i, can take again!

Step-by-step tree example

Coins = [1, 6, 10], S = 12. Minimum coins to make 12.

CC([1,6,10], 12)
├── TAKE 10:  1 + CC([1,6,10], 2)    ← can take 10 again!
│   └── CC([1,6,10], 2)
│       ├── 10>2 → skip: CC([1,6], 2)
│       │   └── 6>2 → skip: CC([1], 2) = 1+CC([1],1) = 2   (two 1s)
│       └── TAKE 10? 10>2 → skip
│       → CC([1,6,10],2) = 2   → Total: 1 + 2 = 3 coins  (10+1+1)
│
└── DON'T TAKE 10:  CC([1,6], 12)
    ├── TAKE 6:  1 + CC([1,6], 6)
    │   └── 1 + CC([1,6],6):  1 + (1+CC([1,6],0)) = 1+1 = 2  → Total: 1+2=3 (6+6)
    └── SKIP 6: CC([1], 12) = 12 coins  (all 1s)
    → CC([1,6],12) = min(3, 12) = 3 coins  (6+6 or 10+1+1)

Answer: min(3, 3) = 3 coins  → e.g., take 10 + 1 + 1, or take 6 + 6

Topic 4

DP vs Greedy vs Divide & Conquer

All three techniques break a big problem into smaller pieces. The difference is in how many subproblems you solve and whether subproblems repeat.

The 2 Properties of Dynamic Programming

1. Optimal Substructure — Can you divide the problem into subproblems? The optimal answer to the big problem is built from optimal answers to subproblems.

2. Overlapping Subproblems — Do different branches of recursion compute the same subproblem repeatedly? If yes, memoize (or tabulate) to avoid re-computation.

Divide & Conquer

Has optimal substructure ✓
No overlapping subproblems ✗
Each subproblem is unique.

Example: MergeSort splits into two halves — they never overlap.

Dynamic Programming

Has optimal substructure ✓
Has overlapping subproblems ✓
Multiple subproblems exist, reused!

Example: Fibonacci, LCS, Knapsack — same sub-call appears from different branches.

Greedy

Has optimal substructure ✓
Only ONE subproblem after each choice!
No branching — commit and reduce.

Example: Fractional Knapsack, Dijkstra, Kruskal — make best local choice, never revisit.

The Greedy Choice Property

Greedy works only when you can prove: "Making this greedy choice does NOT rule out the optimal solution."

In other words: there exists at least one optimal solution that includes your greedy choice. You must prove this for each greedy algorithm.

Note from lecture: In practice, people usually first discover the greedy works (by experimentation), then prove it works after. The proof is more for academic justification than design.

Why DP never needs a "greedy proof"

DP considers ALL possibilities and picks the best. There's nothing to prove — you always get the optimal answer. Greedy takes a shortcut (only one subproblem instead of many) which saves time but requires a correctness proof.

Why Greedy fails for Coin Change (general case)

Greedy: always pick biggest coin

Coins=[25,20,10,1], S=30
Pick 25. Remaining=5. Can't make 5 with {20,10} except using five 1s.
Result: 25+1+1+1+1+1 = 6 coins

DP: considers all options

Coins=[25,20,10,1], S=30
DP tries 20+10 path → 2 coins.
Also tries 25+... path → 6 coins.
Takes min: 2 coins (20+10) ✓

✨ Famous Analogy from the lecture

"Those who cannot remember the past are condemned to repeat it." — Dynamic Programming remembers all past computed subproblems. That's exactly the point of memoization.

Topic 5

Floyd-Warshall Algorithm

What is the problem?

Input: A graph G(V, E) with any edge weights (including negative, but no negative cycles for valid shortest paths).

Output: Shortest path distance between every pair of vertices (all-pairs shortest path).

vs. earlier algorithms: Dijkstra and Bellman-Ford solve single-source shortest path (source fixed). Floyd-Warshall solves it for ALL sources at once.

Key properties (what you must know)

DP Algorithm Works with negative edges No negative cycles required Time: O(V³)

1. It is a DP algorithm — considers all intermediate vertices step by step.

2. Works with negative edge weights — unlike Dijkstra (greedy, needs non-negative). Because DP considers all paths, negative edges don't mislead it.

3. Negative cycle detection: If there IS a negative cycle (e.g. a loop with total weight -10), then the diagonal entries of the output matrix become negative. Why? Because going around the cycle from vertex v back to v costs less than 0 → d[v][v] < 0.

The output: a 2D matrix

The algorithm fills a V×V matrix where entry [i][j] = shortest path cost from vertex i to vertex j.

From\ToV1V2V3V4
V1 0d(1→2)d(1→3)d(1→4)
V2 d(2→1)0d(2→3)d(2→4)
V3 d(3→1)d(3→2)0d(3→4)
V4 d(4→1)d(4→2)d(4→3)0

Diagonal entries are normally 0 (cost to go from V to V = 0). If any diagonal entry becomes negative → negative cycle exists!

Why O(V³)? Algorithm idea

Core DP idea (even if GATE rarely asks internals)

The key idea: for each possible "intermediate" vertex k (from 1 to V), update:
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
Three nested loops: k, i, j → O(V³). We ask: "Is going through vertex k a shorter path from i to j?"

✨ Why Floyd-Warshall is the winner for all-pairs

Running Dijkstra V times = V × (V+E)logV. In dense graphs (E≈V²), this is V³logV. Floyd-Warshall is always exactly V³ — better! Running Bellman-Ford V times can be V⁴ — much worse.

Topic 6

Travelling Salesman Problem (TSP)

What is the problem?

Story: A salesman starts at city A. He must visit every other city exactly once and return to A. Find the route with minimum total distance.

Input: A complete graph of n cities with distances between every pair.

Output: The shortest Hamiltonian cycle (visits all cities exactly once and returns to start).

How many possible routes?

Starting from city A: Remaining cities to arrange = n−1 Possible orderings = (n−1)! For n=4: (4−1)! = 6 routes For n=10: 9! = 362,880 routes For n=20: 19! ≈ 1.2 × 10¹⁷ routes ← impossible to check all!
(n−1)! grows faster than 2ⁿ — super-exponential!
For n=4 cities {A, B, C, D}, all 6 routes starting from A:
  A → B → C → D → A
  A → B → D → C → A
  A → C → B → D → A   ← pick the one with smallest total distance
  A → C → D → B → A
  A → D → B → C → A
  A → D → C → B → A

NP-Hard: The important classification

🔴 NP-Hard Problem

TSP is NP-Hard. This means:

• No polynomial-time algorithm has been found (nobody has P = NP proof yet)

• Nobody has proved a polynomial-time algorithm is impossible either

• The best exact algorithm requires exponential time: O((n−1)!) or with DP optimization, O(n² × 2ⁿ)

• This question — whether polynomial-time TSP exists — remains open (one of the most famous unsolved problems in computer science: the P vs NP problem).

What does "NP-Hard" mean simply?

It means: even the smartest known algorithm takes time that grows too fast to be practical for large inputs. For n=30 cities, (n−1)! = 29! ≈ 8.8×10³⁰ — checking all routes would take longer than the age of the universe. That's why real GPS systems use approximation algorithms instead of exact solutions.

Key Distinctions (Tricky Points)

MSS vs Subset Sum
Both same structure. MSS returns integer, uses max. Subset Sum returns bool, uses OR. Adding w_i only in MSS (not possible in SS since return type is bool).
0/1 Knapsack vs Coin Change
0/1 Knapsack: after taking item i, recurse on i−1 (item used up). Coin Change: after taking coin i, recurse on i (unlimited supply). One index change → huge behavioral difference!
Dijkstra vs Floyd-Warshall
Dijkstra: single source, greedy, no negative edges. F-W: all pairs, DP, handles negative edges. Running Dijkstra V times = O(V³logV) worst. F-W = O(V³) always better for all-pairs.
Negative Cycle Detection (F-W)
After F-W, check diagonal. Normally dist[v][v]=0. If dist[v][v]<0 for any v → negative cycle exists. The v in the cycle will have negative self-distance.
TSP complexity
Brute force: (n−1)!. This is worse than exponential 2ⁿ. DP (Held-Karp algorithm): O(n²×2ⁿ) — still exponential but better. No polynomial solution known. NP-Hard.
Top-Down vs Bottom-Up
Both fill same table, same space complexity. Top-down fills entries ON DEMAND (lazy), can be faster if many entries not needed. Bottom-up fills ALL entries (sometimes unnecessary). For sparse targets, top-down wins.
